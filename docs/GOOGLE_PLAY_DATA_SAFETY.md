# Google Play Data Safety — Android 1.0

Рабочая карта для заполнения формы Data Safety в Play Console. Перед публикацией ответы нужно сверить с фактической production-конфигурацией провайдеров и формулировками, которые показывает Play Console.

## Общие ответы

- Приложение собирает пользовательские данные: **да**.
- Данные шифруются при передаче: **да**, production-клиент разрешает только HTTPS.
- Пользователь может запросить удаление данных: **да** — внутри приложения и на `https://vedelo.ru/account-deletion`.
- Данные продаются: **нет**.
- Приложение предназначено для детей: **нет**, возрастное ограничение — 18+.
- Независимая сертификация безопасности: отмечать только при наличии действующего подтверждения.

| Адрес | адреса мероприятий и реквизитов | нет | функции CRM, документы и навигация |

| Контакты | только контакты, внесенные в CRM; системная адресная книга Android не читается | нет | функции CRM |
| App interactions | действия синхронизации, результат push-действий | да при использовании | работа приложения и защита от дублей |

Пароли, refresh tokens, OAuth secrets и ключи интеграций не относятся к данным, выдаваемым мобильному клиенту: они хранятся в виде хеша либо только на сервере. Системные журналы звонков, SMS, список установленных приложений, точная геолокация и системная адресная книга Android не запрашиваются.

## Передача третьим сторонам

- Expo Application Services и Google Firebase Cloud Messaging обрабатывают push token для доставки уведомлений после явного включения пользователем.
- Google Calendar, VK, Avito, Telegram Business, Novofon и AI-провайдеры получают данные только при добровольном подключении или явном запуске соответствующей функции.
- При заполнении Play Console проверить, подпадает ли каждый production-провайдер под исключение service provider/user-initiated transfer. Если нет — отметить соответствующую категорию как shared.
- Не заявлять отсутствие sharing автоматически: оно зависит от договоров и фактической роли каждого production-провайдера.

## Хранение и удаление

- Серверные данные хранятся до удаления аккаунта либо пока они нужны для предоставления сервиса и выполнения обязательств.
- На Android CRM-кэш хранится в SQLCipher, вложения — AES-256-GCM в app-private каталоге, ключи — в Android Keystore/SecureStore.
- Logout очищает локальную CRM-базу и ставит отзыв серверной сессии в защищенную очередь, если сеть недоступна.
- Удаление аккаунта доступно в профиле приложения и через публичную форму. Запрос требует проверки владения аккаунтом.
