# Промокоды и флаер FOCUS

Версия 1.42.0, 25.10.2026. Web/PWA; production не обновлялся.

## Использование

Пользователь: **Настройки → Общие настройки → Промокод**. Раздел доступен
даже без действующего тарифа. Код не зависит от регистра и пробелов по краям.
Один аккаунт может использовать каждый код ровно один раз.

Администратор/dev: **Администрирование → Промокоды**. Создание и редактирование:
код, бонус в рублях, конкретный скрытый тариф, последний день активации,
состояние и комментарий. Сумму и тариф можно сочетать. Комментарий доступен
только администратору. Код неизменяем: для новой кампании создаётся новый код.
Вместо удаления используется отключение, сохраняющее историю одноразовости.

Выдача доступа к тарифу бесплатна и не меняет текущую подписку. Подключение
и оплата выполняются обычным выбором тарифов; доступ открывается только к
указанному тарифу. Срок кода ограничивает активацию, а не длительность доступа.
Истечение/отключение кода не отзывают выданное разрешение. Обычное управление
персональными тарифами администратором сохраняется.

Дата в редакторе включительна: сохраняется 23:59:59.999 в часовом поясе
браузера администратора. API хранит точный момент UTC. В другом часовом поясе
список показывает тот же момент в местном времени.

## Настройка FOCUS после обновления

По решению владельца тариф настраивается им самостоятельно:

1. Создать/настроить скрытый **BRO**: **400 ₽/месяц**, все функции тарифа «БИЗНЕС», включая 300 ₽ ИИ в месяц.
   Предложение FOCUS: пожизненная скидка 50% относительно «БИЗНЕС» за 800 ₽.
   Промокод предоставляет постоянный доступ к BRO; цена задаётся настройками
   самого тарифа, автоматической формулы скидки от другого тарифа нет.
2. Создать промокод **FOCUS**, бонус **0 ₽**, скрытый тариф **BRO**.
3. Последний день активации **31.10.2026**, состояние **Включён**.
4. Комментарий: «Флаер A6 с комиксом для фокусников».

Исходники не создают и не меняют реальные тарифы или промокоды автоматически.
До настройки и выкладки FOCUS на production не активируется.

## Серверный контракт

### Просмотр использования и удаление (1.42.1)

Карточка показывает число уникальных пользователей и кнопку «Кто воспользовался».
Модальное окно содержит имя/телефон, дату, первоначальный бонус и название тарифа;
список загружается по 50 записей. В административном просмотре пользователя
показывается блок использованных промокодов, если история непустая.

GET `/api/admin/promo-codes` возвращает usageCount/canDelete. Параметры `code/page`
дают список пользователей, `userId` — безопасную историю выбранного пользователя.
Это явная межтенантная административная выборка; обычным аккаунтам и impersonation
она запрещена, скрытые служебные снимки в общий user CRUD не добавлены.

DELETE принимает `{code, revision}` и удаляет только неиспользованный промокод.
Активация атомарно увеличивает `activeRedemptions` при `deleting != true`;
удаление захватывает `deleting` только при нулевом/отсутствующем счётчике,
затем проверяет все снимки Users, включая архив. Завершённая попытка активации
освобождает счётчик в finally; неуспешное удаление снимает свой lock.
Повторное начисление и восстановление Payments по старому снимку сохранены.

При аварийном завершении процесса или неизвестном результате Mongo-записи lock
может остаться: удаление блокируется безопасно. Автоматический сброс по времени
не используется. Снимать lock вручную можно только после остановки всех старых
обработчиков, проверки отсутствия активных запросов и сверки Users.promoRedemptions.
При выкладке все обработчики активации должны быть обновлены: старая версия не
учитывает блокировку удаления.

Проверка 1.42.1: 12/12 серверных тестов на временной standalone MongoDB,
точечный ESLint и git diff --check прошли. Playwright/Edge проверил реальные
карточки, стандартный стек модалок, блок истории и userViewFunc на 390/1365 px
в обеих темах: список/пагинацию/пустое состояние, отмену/ошибку/успех удаления,
непустую и пустую историю пользователя. API и сторонние элементы профиля в
стенде подменены; ошибок console/pageerror нет. Production и полная сборка
в этой итерации не запускались.

- `GET/POST /api/admin/promo-codes`: admin/dev без impersonation, global каталог
  платформы `PromoCodes`. Обычные пользователи каталог не получают.
- `POST /api/promo-codes/redeem`: web/mobile request context, принимает только
  `{code}`, tenant/пользователь из проверенной сессии; лимит 15 попыток/минуту
  на комбинацию IP/tenant/user. В нативном Android UI поле пока не добавлено.
- Код нормализуется в uppercase; SHA-256 — стабильный первичный ключ каталога.
  Переименование и повторное создание через другой регистр не обходят защиту.
- `Users.promoRedemptions[hash]` — скрытый снимок первоначального начисления.
  Баланс, конкретный `allowedTariffIds` и снимок изменяются атомарно в Users;
  `billingRevision` инвалидирует конкурирующее решение о подписке. На самой
  записи проверяется, что срок ещё не истёк. Generic user CRUD не меняет снимки.
- На начало активации берётся текущая конфигурация кода. Уже начатая активация
  может завершиться со снимком до одновременного редактирования/отключения кода.
- Бонус отражается в Payments как `system/topup/balance` с детерминированным
  ID: это бонус, а не внешнее денежное поступление или реферальная операция.
  Комментарий администратора в платёж/пользовательский ответ не копируется.
- Users и Payments не являются общей транзакцией: сбой записи истории после
  начисления возвращает 503 с просьбой повторить код. Повтор сверяет скрытый
  снимок и восстанавливает историю без новых денег/доступа даже после истечения
  срока, изменения условий или отключения. Автоматического фонового ремонта
  истории нет. Не удалять `promoRedemptions` вручную.
- Редактирование конфигурации использует `revision`: устаревшая запись — 409.

## Печать

`public/marketing/comics/fokusniki/flyer-back-a6.pdf` — оборот;
`flyer-duplex-a6.pdf` — две страницы: существующий комикс и оборот.
Обрезной размер **105 × 148 мм**, вылеты **3 мм**, MediaBox **111 × 154 мм**,
TrimBox/BleedBox заданы. PDF содержит встроенные шрифты и векторный QR
`https://vedelo.ru`. Комикс размещён целиком без обрезки с полями 5 мм
со всех сторон, как на обороте; пропорции слегка адаптированы к этой области.
Печать 100%, без «вписать в страницу». Цветовой профиль типографии не задан:
PDF использует RGB; при необходимости CMYK-конверсию выполняет типография.

Пересборка: `python scripts/buildFocusFlyer.py` (Windows Arial/Georgia,
reportlab, pymupdf). Превью `flyer-back-a6.png` создаётся тем же скриптом.
