# Первый вход в ArtistCRM

Обновлено: 2026-09-13. Версия: 1.18.4.

## Пользовательский сценарий

Первый вход состоит из четырёх шагов: ФИО, город/часовой пояс, специализация и услуги. Фото и контакты находятся под «Добавить подробности». На шаге услуг предлагается одна услуга; цена, длительность и описание раскрываются отдельно. Название услуги обязательно, нулевые цена и длительность допустимы. Если у пользователя уже есть хотя бы одна услуга, мастер не предлагает создавать новую: шаг можно пропустить и завершить настройку.

На втором шаге можно выбрать светлую или тёмную тему компактными кнопками со значками солнца и луны. Выбор применяется сразу и сохраняется в текущем браузере (`localStorage.theme`), как в настройках кабинета. До выбора сохраняется текущая тема; при недоступном хранилище переключение действует в текущем сеансе. Число шагов остаётся прежним. Поля города и часового пояса ограничены шириной 288 px и сужаются вместе с экраном. Передача заказа коллеге остаётся в настройках. Каждый успешно сохранённый шаг фиксирует следующий шаг; после перезагрузки незавершённая настройка продолжается. При ошибке сохранения перехода нет. Введённые, но ещё не сохранённые данные после перезагрузки не восстанавливаются.

После обязательной настройки пользователь выбирает «Показать на примере» или «Перейти в кабинет». Обучение показывает заявку, назначение контакта, подтверждение и контроль задатка на одной учебной карточке. Его можно прервать в любой момент и повторить из «Настройки → Начало работы». Финальный переход ведёт во «Важное»; для нового пустого кабинета предлагается создать свою первую заявку.

При повторном открытии уже завершённого мастера доступна кнопка «Вернуться в кабинет». Она закрывает окно без перехода на другую страницу и без сохранения текущего незавершённого шага; ранее сохранённые шаги остаются сохранёнными. Во время сохранения закрытие заблокировано. При первом обязательном запуске кнопка не показывается.

В специализации добавлен вариант «Ремонт, монтаж и бытовые услуги» (`repair_home`): электрик, маляр, сантехник, сборщик мебели, мастер по ремонту и клининг. Предлагается услуга «Ремонтные и монтажные работы», которую пользователь переименовывает под свою специальность. Учебный пример — работы в квартире с уточнением объёма, материалов, сроков и оплаты. Мобильный API получает новый вариант из общего списка пресетов.

Также доступны «Перевозки и доставка» (`transport_delivery`) и «Дизайн, разработка и маркетинг» (`digital_services`). Для них предлагаются соответственно перевозка/доставка и работа над проектом; названия можно изменить. Учебные примеры — перевозка мебели и обсуждение нового проекта. В подсказках эти работы называются заказами.

## Хранение и совместимость

- `siteSettings.custom.firstRunWizardStep`: следующий незавершённый шаг (`profile`, `environment`, `specialization`, `services`), после завершения — `null`.
- `firstRunWizardCompleted`: обязательные данные сохранены. Автопоказ для уже завершивших настройку не меняется; неизвестный старый шаг начинает мастер с первого экрана.
- `firstRunTourResult`: `completed` или `skipped`. Повторный запуск доступен независимо от значения. При отсутствии сети можно выйти из обучения без сохранения результата.
- `onboardingActivityPreset` и `onboardingStarterServicesCreated` переиспользуются. Другие настройки, включая передачу коллеге, сохраняются.
- Учебная карточка использует только React state: она не вызывает API мероприятий, клиентов, транзакций, календаря и уведомлений. На выходе сохраняется только результат обучения в настройках. Учебные действия не отправляют события реальных заявок/активации.
- `onboarding_complete` отправляется после сохранения всех обязательных данных. Раньше событие отправлялось после шага города/времени, поэтому показатели до и после изменения не следует считать полностью сопоставимыми.

ФИО пользователя в мастере и редакторе вводится одной строкой, аналогично клиентам. Старые три поля объединяются через `getPersonFullName` с сохранением существующего порядка. При сохранении полная строка записывается в `firstName`, остальные два поля очищаются; автоматического разбора слов нет. Поле обязательно, отчество необязательно. Максимальная длина `firstName` увеличена до 302 символов, чтобы вместить три прежних поля с пробелами. Массовой миграции нет, контракты API сохраняются.

Мобильная проверка при отсутствии сети больше не требует отдельного `secondName`; основной серверный признак завершения onboarding сохраняется. Мобильное сохранение профиля допускает полную строку без обрезки до прежних 100 символов. Повторный VK-вход не дописывает фамилию к уже заполненному пользователем имени.

## Проверки и ограничения

Автоматически проверяются прогресс, ФИО старого/нового формата, ошибки сохранения, повторный запрос во время сохранения, частичное сохранение услуг и изоляция учебных действий. Команды:

```sh
node --test helpers/firstRunWizard.test.mjs helpers/personName.test.mjs helpers/onboardingPresets.test.mjs tests/components/firstRun.test.cjs server/mobile/profile.test.js
```

Браузерная проверка выполняется на локальном стенде с настоящими компонентами и стилями, заменёнными сохранением в памяти и маршрутизацией. Это проверка UI, не production E2E. На стенде пройден путь от ФИО до завершения учебной оплаты; проверены узкая компоновка и светлая/тёмная темы. Рабочая БД и реальные интеграции в проверке не используются.

Перед релизом остаются проверка в авторизованном кабинете с тестовым tenant, системная клавиатура на телефоне и пользовательское тестирование с пятью новичками. Критерий гипотезы: четверо из пяти без объяснений проходят настройку и находят создание заявки, следующий контакт и контроль задатка. Эти внешние проверки не считаются выполненными автоматически.
