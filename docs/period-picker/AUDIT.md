## Не являются произвольным диапазоном фильтра/импорта

- `StatisticsContent.js` / `StatisticsSection.tsx`: выбор года для годового графика (или всех лет), не поля произвольного диапазона. Не подменять год календарным диапазоном без изменения аналитического контракта.
- Одиночные дата оплаты/документа/срок предложения, дата и время начала/окончания самой работы, дата рождения, календарная навигация месяца: их формат и смысл не менять.
- Сроки тарифов и вычисляемые интервалы в тексте не являются контролами выбора периода.

## Одобренный дизайн-контракт

На странице одно поле с песочной подписью, календарём слева и шевроном справа. Использовать InputWrapper, AppButton и реальные токены темы, не локальную копию цветов прототипа. Сброс рядом: на телефоне круглая кнопка с иконкой и доступным именем, на компьютере овальная кнопка с подписью. Сначала открывается только список быстрых периодов; календарь — отдельный шаг «Выбрать даты»; ручной ввод ДД.ММ.ГГГГ скрыт до запроса. Готовые периоды применяются сразу; произвольный диапазон только после «Применить», закрытие/назад/отмена не меняют внешнее значение. Полный диапазон виден/доступен, конечный день включён, открытые границы разрешены только потребителям, которые уже их поддерживали. Дополнительные быстрые варианты транзакций не удалять.

Обязательные тесты: новый тест красный до реализации; настоящие компоненты и CSS в Chromium, light/dark, 280/390/1365 и короткая высота, клавиатура/фокус/вложенная модалка, cancelled draft, invalid calendar dates, reversed range, same day, open boundaries, min/max/maxDays, disabled, отметки активных дат. Интеграционные тесты должны проверять фактические значения потребителей, а не копию обработки в заглушке.
