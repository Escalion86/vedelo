# Восстановление списка «Что за событие?»

Запускать из корня проекта. Скрипт `scripts/restoreEventTypes.cjs` берёт непустые
строковые `eventType` из мероприятий выбранного tenant, исключая `isDemo: true`.
Он добавляет недостающие варианты в `SiteSettings.custom.eventTypes`, сохраняя
существующие варианты и остальные настройки. Мероприятия не изменяются.
Пробелы по краям убираются; регистр сохраняется. Повторный запуск не создаёт
дубликаты. Изменение увеличивает `syncVersion` и обновляет `updatedAt`.

Для единственного аккаунта разработчика сначала выполнить предварительный просмотр:

```powershell
node --env-file=.env.local scripts/restoreEventTypes.cjs --developer
```

Применить:

```powershell
node --env-file=.env.local scripts/restoreEventTypes.cjs --developer --apply
```

Подключение определяется `MONGODB_URI` и `MONGODB_DBNAME`. Уже заданные переменные
окружения имеют приоритет над env-файлом. Вместо `--developer` можно использовать
`--tenant=ID_ОРГАНИЗАЦИИ` (24 шестнадцатеричных символа) или `--all` для всех
аккаунтов. Если разработчиков несколько, нужен явный tenant. Без `--apply`
скрипт только считает изменения; персональные данные и названия типов не выводятся.

`accountsToUpdate` — число аккаунтов с недостающими вариантами; `typesToAdd` —
сумма добавляемых вариантов; `accountsUpdated` — фактически обновлённые аккаунты.
При конкурентном изменении списка скрипт пропускает конфликтную запись:
`conflicts > 0`, код выхода 2; следует повторить предварительный просмотр.
При ошибке возможны уже выполненные изменения предыдущих аккаунтов, повтор безопасен.
Дубли документов настроек и некорректные типы полей требуют отдельной диагностики.

Скрипт возвращает также ранее намеренно удалённые варианты, если они встречаются
в мероприятиях. Варианты, которые никогда не использовались, восстановить таким
способом нельзя. После применения обновите страницу кабинета.

## Объединение ФИО клиентов

Существующий скрипт `scripts/mergeClientFullNames.js` сам загружает `.env.local`.

```powershell
node scripts/mergeClientFullNames.js
node scripts/mergeClientFullNames.js --apply
```

Первый запуск — предварительный просмотр для всех клиентов, второй — применение.
Для одной организации добавьте `--tenant=ID_ОРГАНИЗАЦИИ`. Скрипт объединяет
`firstName`, `secondName`, `thirdName` в `firstName` и очищает два остальных поля;
это миграция клиентов, а не профилей пользователей. Скрипт выводит только количества,
без ФИО. `planned` — найдено для объединения, `modified` — записано,
`conflicts` — пропущено из-за параллельного изменения ФИО (код выхода 2).
Повторный запуск безопасен; клиенты без корректного tenantId пропускаются.

Если файл окружения называется `.env`, используйте:

```bash
node --env-file=.env scripts/mergeClientFullNames.js
node --env-file=.env scripts/mergeClientFullNames.js --apply
```

Ошибка `Update document requires atomic operators` в прежней версии возникала
из-за пустой strict-схемы Mongoose. Скрипт теперь использует нативную коллекцию,
сохраняет фильтр tenant и проверяет исходные поля ФИО перед записью.
