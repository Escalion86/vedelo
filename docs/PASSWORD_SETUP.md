# Установка и смена пароля — 1.32.2

## Поведение

В Web/PWA и Android пользователь, уже вошедший через VK или другим способом, может установить отдельный пароль Ведело прямо в профиле.

- Если пароля нет: «Установка пароля», новый пароль и его повтор, кнопка «Установить пароль». Текущий пароль не запрашивается.
- Если пароль есть: «Смена пароля», текущий пароль, новый пароль и повтор, кнопка «Сменить пароль».
- Минимум нового пароля — 8 символов. Поля скрыты до загрузки актуального состояния. Ошибка загрузки не считается отсутствием пароля; есть повтор загрузки.
- После установки доступен вход по сохранённому номеру телефона и новому паролю. Привязка VK и пользовательские данные не меняются.
- Пароль от VK не запрашивается. Для установки первого пароля достаточна действующая сессия Ведело; дополнительная телефонная проверка не добавлялась.
- Android сохраняет прежнее поведение: отзывает мобильные сессии и выдаёт текущему устройству новую. Web-сессии NextAuth не аннулируются автоматически.

## Реализация и безопасность

`server/passwordChange.js` используется обоими обработчиками:

- `/api/auth/change-password`: GET `{ success, hasPassword }`; POST `{ currentPassword?, newPassword }` → `{ success, mode, hasPassword }`.
- `/api/mobile/v1/auth/change-password`: GET `{ success, data: { hasPassword } }`; POST с прежним payload возвращает прежний AuthSession DTO.

GET имеет `Cache-Control: no-store`. Пароль и его хеш клиенту не выдаются. Сервер сам проверяет наличие пароля в БД, игнорирует клиентские `hasPassword`, `userId`, `tenantId`. Используется фильтр текущего пользователя и tenant, архивные пользователи исключены. При установленном пароле отсутствие или ошибка текущего запрещает изменение. `findOneAndUpdate` проверяет старое значение атомарно: параллельная установка не может перезаписать уже установленный пароль. Пароль хранится как bcrypt-хеш; legacy-пароли поддерживаются при смене.

Повтор нового пароля проверяется в интерфейсе, но не требуется от установленного старого APK: совместимость API сохранена.

## Проверки

Серверные и веб-компонентные проверки:

```bash
node --test tests/server/passwordChange.test.cjs tests/server/passwordRoutes.test.cjs tests/components/changePasswordModal.test.cjs
```

Android-профиль и типы:

```bash
cd mobile
npx jest src/features/profile/ProfileScreen.test.tsx --runInBand --silent
npm run typecheck
```

Браузерный стенд собирает настоящую модалку, поля и CSS проекта; подменяются только ответы API и доставка уведомлений. Проверяются установка, смена, неправильный текущий пароль, несовпадающий повтор, отсутствие переполнения, 390/1365 px, обе темы:

```bash
ESBUILD_MODULE=/absolute/path/to/esbuild PLAYWRIGHT_MODULE=/absolute/path/to/playwright node --test tests/components/password.browser.test.cjs
```

HTTP-проверка требует локального Next-сервера на `PASSWORD_TEST_BASE_URL`, той же тестовой `NEXTAUTH_SECRET` и отдельной локальной MongoDB `127.0.0.1:27029`, базы `vedelo_password_test`. Создаёт только синтетические аккаунты, проверяет настоящий bcrypt, запись/гонку в MongoDB, оба API, вход по новому паролю, запрет старого, отзыв Android-сессий. Production-URI и реальные аккаунты не используются:

```bash
PASSWORD_TEST_BASE_URL=http://127.0.0.1:3099 NEXTAUTH_SECRET=local-test-secret node --test tests/server/passwordHttp.integration.test.cjs
```

Проверены: 15 серверных/веб-компонентных тестов, 9 Android-компонентных тестов, TypeScript, адресный ESLint, браузерный стенд во всех четырёх сочетаниях темы/ширины, проверки адаптивности 280/320/414 px и размеров элементов.

Дополнительно прошли 9 регрессионных тестов мобильных сессий, профиля и токенов. Production-сборка 1.32.2 прошла на отдельной локальной MongoDB.
