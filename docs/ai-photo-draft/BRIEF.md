## Требования этапа (одна функциональность)
1. Web/PWA пункт «Из фотографии» только allowAi, shared menu hook (чтобы и desktop FAB получил возможность). Выбор изображения и отдельный снимок камерой на телефоне, предпросмотр, замена/отмена, понятные loading/disabled/error. Согласованные компоненты и тематические токены, доступные подписи. Фото не загружать и не анализировать до явного «Распознать и заполнить». Напомнить о проверке распознанного текста/полей и обычной тарификации ИИ.
2. Реальный серверный endpoint (предпочтительно /api/events/ai-photo-draft, mobile alias), session/bearer auth, allowAi проверяются ДО чтения/декодирования изображения и внешнего запроса. Только JPEG/PNG/WebP с проверкой реальных байтов sharp, ограничение файла 5 МБ, числа пикселей и body длины до тяжелого декодирования. Нормализовать EXIF-ориентацию/метаданные и уменьшить снимок для ИИ. Не принимать URL/SSRF/SVG и не записывать фото/контакты в логи. Фото временно в памяти, не размещать публично.
3. Использовать настоящий multimodal provider для OCR. Не выдумывать поля и не делать regex fallback для нераспознанного/ошибочного изображения. Для неизвестной/не vision модели или DeepSeek возвращать понятную безопасную ошибку без расхода на очевидно неподдерживаемую модель. Обычная платная обработка должна использовать aiBilling с текущим tenant/user и резервом/возвратом на ошибках. Нельзя скрыто отправлять фото другому платному провайдеру. Можно OCR → существующая обработка текста (две операции, явно указать это в диалоге/документации). Возвращать исходный распознанный текст вместе с тем же fields/client/aiFilledFields/aiWarnings. Без читаемого текста — 422, ошибки провайдера — безопасные 502/503, баланс — 402. Подсказать переснять/выбрать другое фото.
4. Повторное использование существующей обработки заметок вместо дублирования сложного matching: вынести общую функцию/handler, сохранить авторизацию/tenant фильтры и совместимость text/voice. Сервер не сохраняет EVENT сам. Существующий побочный эффект создания клиента не расширять произвольно; источники только распознанный текст. Не отправлять чужие каталоги провайдеру, не принимать tenant из payload.
5. Подложка заголовка центрального меню: плотный фон темы, рамка/отступы, читаемые текст/контраст обеих тем, без изменения цветов всей навигации. Заголовок не накладывается на кнопки; 4 пункта влезают/прокручиваются на коротком экране. Если native уже имеет плотную панель, не рестайлить её без нужды.
6. Native Android: добавить photo route choice / initialMode (или отдельный фото-компонент) и тот же server API с bearer. Выбор/камера с обработкой отказа разрешений, отмены, offline, лишнего/битого файла. Не допускай автоматического повтора платного POST после 401 (используй skipRefresh=true в api). Existing text/voice поведения не менять. Использовать установленные Expo зависимости, не добавлять новые без необходимости. Проверить TypeScript + целевые Jest.
