# Черновик из фотографии (Web/PWA и Android)

Временный запуск 1.35.1: «Из фотографии» доступно только пользователю с ролью `dev` и действующим тарифом с `allowAi`. Ограничение проверяется в Web/PWA, Android и на сервере до чтения тела/запроса к ИИ; admin и обычные пользователи не имеют доступа. Голосовой и текстовый ввод не ограничиваются ролью.
Можно выбрать изображение или отдельно снять заметку камерой. Выбор, предпросмотр,
замена и отмена не отправляют изображение на сервер. «Распознать и заполнить»
выполняет OCR и структурирование, показывает исходный распознанный текст.
Следующее явное действие переносит результат в обычный редактор. Заказ/мероприятие
сохраняется только обычной кнопкой сохранения. Проверяйте имена, контакты, даты,
адрес и суммы по оригиналу: OCR, особенно рукописный, может ошибаться.

## API

`POST /api/events/ai-photo-draft`, alias
`POST /api/mobile/v1/events/ai-photo-draft`; JSON:

```json
{ "image": "data:image/png;base64,..." }
```

Только JPEG/PNG/WebP, до 5 MiB, 20 миллионов пикселей, один кадр.
Максимум тела — `ceil(5*1024*1024/3)*4 + 2048` байт (base64 + JSON).
Тело читается ограниченным потоком, даже без Content-Length. Авторизация через
существующий cookie/bearer `getRequestContext`, затем серверный `allowAi` —
до чтения тела. Tenant/owner/client IDs из payload не принимаются.
Проверяются base64, сигнатура и фактический формат через sharp, полный decode,
число пикселей. EXIF-ориентация применяется, метаданные/GPS удаляются; для ИИ
формируется JPEG до 1600×1600. URL, SVG и анимированные файлы запрещены. Фото
остаётся в памяти запроса; публичное/облачное хранение и новые схемы не нужны.

Ответ: прежние `fields`, `client`, `clientCreated`, `aiFilledFields`, `aiWarnings`
плюс `sourceText`. `Cache-Control: private, no-store`.
Ошибки: 401 auth, 403 tariff, 400 неверный файл/тело, 413 предел файла/тела/пикселей,
422 нет читаемого текста/текст длиннее 12000 символов, 402 баланс,
503 отключённый/неподдерживаемый vision, 502 provider/невалидный результат.
Ошибки предлагают переснять заметку или выбрать другое фото; сырые upstream
ошибки, изображение, контакты и ключи не логируются и не возвращаются.

## Провайдер и оплата

Выбранный пользователем провайдер и модель сохраняются. Поддерживается
консервативный перечень image-input моделей: `gpt-4o-mini`,
`gpt-4o-mini-2024-07-18`, `gpt-4o`, `gpt-4o-2024-05-13`,
`gpt-4o-2024-08-06`, `gpt-4o-2024-11-20` у общего/личного AITunnel
или OpenAI-compatible конфигурации. DeepSeek и неизвестная модель получают
503 до внешнего запроса и резерва; автоматического переключения на другого
провайдера нет. Возможность image-input подтверждена
[документацией GPT-4o mini](https://developers.openai.com/api/docs/models/gpt-4o-mini).
Наличие конкретной модели у выбранного upstream определяется провайдером;
неподдерживаемый им запрос возвращает безопасную ошибку.

Это **две обычные операции ИИ**: `event_photo_ocr` → `event_draft`.
Обе используют `requestAiChatCompletion`, текущие tenant/user и `aiBilling`.
В billing обе записываются совместимым `feature=event_draft`; отдельный логический
тип OCR не требует нового enum или миграции схемы.
У платформенного ArtistCRM/AITunnel есть резерв перед каждой операцией, расчёт
фактического usage, возврат резерва при network/HTTP/пустом provider response.
Личный AITunnel оплачивается его владельцем, платформенного списания нет.
Успешно выполненная операция оплачивается, даже если текст не найден, модель
вернула некорректный JSON или следующий этап не выполнен; это не атомарный пакет
с общим возвратом. При 402 на втором этапе OCR уже может быть оплачен.
Повторное нажатие после ошибки — новый платный запуск, явный выбор пользователя.
После успешного OCR перенос в форму и повтор применения в native не вызывают ИИ.

OCR получает только изображение и инструкцию переписать читаемый текст.
Общий `server/eventAiDraft.js` структурирует именно `sourceText`, сопоставляет
только текущий tenant-каталог и сохраняет прежний побочный эффект текстового
ввода: если в заметке есть новый подтверждённый контакт, может создать клиента.
Фото-ветка использует `strict`, без regex-fallback при ошибке провайдера/JSON.
Прежний text/voice fallback сохраняется. EVENT этот API не создаёт.

## Android

`mode=photo` в штатном `/events/edit/new`, отдельная `PhotoDraftSection`,
проверки доступа/сети, permissions/cancel/error, предпросмотр и явное применение.
Платный POST передаёт `skipRefresh: true`, поэтому 401 не вызывает автоматического
повтора. Поля/услуги проверяются по доступным ID; новый клиент повторно читается
через защищённый GET перед добавлением в существующий cache и выбором.
Ошибки применения сохраняют распознанный результат для повторного применения.

Добавлен необходимый `expo-image-picker ~55.0.24` (Expo SDK 55), вместе с
`expo-image-loader`; ранее камера изображений не была установлена. Для его
нативного кода нужна следующая сборка владельцем; текущий установленный APK
не обновляется этим изменением. Версия/buildNumber/package ID не менялись,
APK/AAB не выпускались. iOS и физическая камера не проверены.

Фактическая приёмка и команды — [REPORT.md](REPORT.md).
