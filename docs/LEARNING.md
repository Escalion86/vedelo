# Обучение и полезные советы

Первая версия: Web/PWA, 1.23.0, 22.09.2026. Нативный Android не изменён.

Обновление 23.09.2026, 1.23.3: тарифные пометки у недоступных функций.

## Пользовательский сценарий

- Раздел `/cabinet/learning`: боковое меню «Поддержка → Обучение»; на телефоне «Меню → Поддержка → Обучение».
- Десять коротких текстовых инструкций сгруппированы по задачам. Каждая раскрывается на месте и содержит переход в рабочий раздел. Переход не создаёт рабочие записи.
- Кнопка «Показать на примере» запускает существующий `firstRunTour`; учебные действия остаются локальными, как описано в `FIRST_RUN_ONBOARDING.md`.
- Ссылка `?article=<id>` раскрывает материал, прокручивает к нему и переводит клавиатурный фокус на его заголовок.
- «Отметить прочитанным» — явное действие. Простое раскрытие инструкции не считается прочтением.
- В «Важном» карточка «А знали ли вы, что…» расположена после рабочего обзора. Она не использует toast, push или уведомления «Что нового».
- Крестик скрывает текущий совет до следующего допустимого показа. «Уже знаю» и прочтение исключают материал из последующих автоматических показов.
- Настройка «Показывать полезные советы в „Важном“» отключает только карточку; каталог доступен в том числе без действующего тарифа. Доступность рабочих функций определяется существующими тарифными проверками.

## Частота и прогресс

`LearningProgress` / коллекция `learningprogresses` хранит отдельный документ для пары `(tenantId, userId)`. Прогресс не находится в общих настройках организации.

День использования — уникальная календарная дата UTC, определяемая сервером. Кабинет отправляет `visit` после завершения обязательной настройки, когда нет открытых модалок. Несколько вкладок или устройств не увеличивают счётчик за одну дату. Дни отсутствия не считаются активными.

Первый показ доступен сразу. Следующий совет выбирается только при открытии «Важного» (`present`), когда счётчик дней использования увеличился минимум на три с предыдущего выбора. Например, показы на 1-й, 4-й, 7-й активные дни. Повторное открытие в тот же день не меняет совет. Выбор идёт по порядку каталога, затем по кругу, пропуская прочитанное и уже известное. Когда всё изучено, карточки нет. Закрытый крестиком материал может встретиться после остальных неизученных.

Запросы активности кэшируются TanStack Query на день и разделены по tenant и пользователю; сервер дополнительно обеспечивает идемпотентность. При ошибке автоматического запроса карточка не мешает работе. Ошибки явных отметок показываются через `Notice`, действие можно повторить. При недоступности сервера каталог остаётся читаемым; отметки не сохраняются в offline-очередь.

API `/api/learning`:

- `GET` — персональный прогресс без записи.
- `POST` — `visit`, `present`, `read`, `known`, `dismiss`, `preference`.
- Для `read`, `known`, `dismiss` нужен `articleId`; для `preference` — boolean `enabled`.
- Идентичность берётся из `getTenantContext()`. Лишние поля, подмена tenant/user, операторы Mongo и неизвестные материалы отвергаются.
- Все Mongo-фильтры содержат tenant и пользователя. DTO не раскрывает идентификаторы владельца.
- Уникальный индекс пары и compare-and-swap по `revision` сохраняют конкурентные изменения без Mongo-транзакций. Кэш не заменяет более новую ревизию устаревшим ответом.

## Добавление материала

### Тарифные ограничения

Материалы не скрываются и не исключаются из советов из-за тарифа. Если функция недоступна, рядом с заголовком в каталоге и в карточке совета показывается «Доступно с тарифа „Название“». В раскрытой инструкции есть пояснение и кнопка «Посмотреть тарифы» вместо перехода к недоступной функции; чтение и отметка о прочтении доступны всегда.

Доступ определяется общим `getUserTariffAccess`, включая пробный период и ограниченное регистрационное предложение. Название берётся из актуального списка тарифов: выбирается самый дешёвый публичный тариф с нужной функцией. Скрытые тарифы не предлагаются, но доступ на текущем скрытом тарифе учитывается. Если более дорогие тарифы не включают функцию, используется точное «Доступно на тарифе „Название“». Если подходящих публичных тарифов нет, показывается «Недоступно на текущем тарифе» без выдуманного названия.

В статье поле `requiredFeature` задаёт ограничение: `allowDocuments` для вложений и шаблонов, `allowCalendarSync` для синхронизации Google Календаря, `allowAi` для импорта из файла (как в действующем экране импорта). При добавлении новых значений нужно сверять реальную проверку доступа в рабочем UI/API и расширять resolver, если флаг имеет особые правила совместимости. Обычные материалы оставляются без `requiredFeature`. Тарифные проверки рабочих API не изменяются.

Resolver: `helpers/learningAccess.mjs`; hook: `helpers/useLearningAccess.js`. После изменения текущего пользователя/тарифов пометки и рабочие ссылки пересчитываются.

Каталог: `helpers/learningCatalog.mjs`. Добавьте постоянный ID в `LEARNING_IDS` и статью в `getLearningArticles`: `id`, `category`, `title`, `summary`, `steps`, `href`, `action`.

Опубликованные ID не переименовывать: на них ссылаются сохранённые отметки и прямые ссылки. Тексты должны соответствовать реальным контролам. Формы заказов/мероприятий брать из аргумента `terms`, который приходит из общего resolver. Не писать HTML и не добавлять внешние ссылки для рабочих переходов. Материалы выпускаются вместе с кодом; отдельного редактора публикаций в этой версии нет.
