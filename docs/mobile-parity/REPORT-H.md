## P — «Клиент и контакты»

- **Основной клиент**: новый `ClientPickerField` — поиск (`clientSearch.ts`) по имени/телефону (нормализация цифр)/соцсетям/email, до 20 вариантов с подсказкой, исключение занятых контактов, «Сменить», «Очистить выбор», карандаш открывает существующий редактор клиента. Для выбранного клиента — существующий `QuickContacts` (быстрые контакты, web-паритет).
- **Создание клиента**: кнопка «Новый клиент» → существующий `mobile/app/clients/edit/[id].tsx` c `returnTo=event`; после сохранения `setPendingEventClient(entity._id)` + `router.back()`. Возврат: одноразовый `eventClientHandoff` (URL не может вернуть значение), редактор работы на focus подхватывает id, если клиент есть в локальном кэше. Клиент создаётся прежней мутацией `saveLocalEntity('clients', entityId: undefined)` — local ID и очередь не менялись.
- **Дополнительные контакты**: пикер исключает основной и уже выбранные, поле «Кем является» (комментарий), удаление; проверка дублей и занятости сохранена в `validateEventDraft`/`serializeEventDraft` (негативный сценарий «контакт недоступен» покрыт прежним тестом).
- **Задачи**: создание, правка (что сделать/когда/комментарий), выполнение `done` + `doneAt` (повторное нажатие снимает), фильтр «Показывать выполненные» (все выполненные скрыты по умолчанию, пустая выдача подписана), удаление сохранённой задачи (`_id`) — только через Alert-подтверждение, новой — сразу. Всё живёт в общем `EventDraft` и записывается только явным сохранением работы через `usePreventRemove`-защиту.

## Q — «Финансы и Документы»

- **Финансы**: «Договорная сумма», «Ждем задаток» → «Сумма задатка»/«Дата ожидания задатка», «Комментарий по финансам», «По договору». `eventForm.ts` сериализует `financeComment`, `isByContract`; задаток — только при `waitDeposit`, иначе `null`/`false`.
- **Оплаченный задаток (факт)**: при фактической транзакции дохода с категорией `deposit`/`advance` поля ожидания скрываются с пояснением, а сохранение обнуляет `waitDeposit`/сумму/срок — как скрывает и обнуляет web (`hasDepositTransaction`).
  - **Сознательное расхождение с web**: обязательства (`paymentMethod='obligation'`) не считаются фактом оплаты задатка. Web берёт любые income с категорией из списка, включая обязательство; BRIEF требует «обязательства отдельно от факта», а обнуление ожидания по плану теряло бы данные. Зафиксировано тестом `eventFinance.test.ts`.
- **Транзакции работы**: только с точным `eventId` (пустой id не подставляет ничего); группы «Поступления/Расходы/Обязательства», чип «Обязательство», строки «Факт: поступления X · расходы Y» и «Обязательства: Z», подпись даты «Плановая дата» для обязательства. Ошибка чтения → Notice + «Повторить загрузку транзакций», без нулевой подмены; при ошибке чтения сохранение не обнуляет поля задатка.
- **Добавление/правка/удаление транзакции**: существующий `mobile/app/finance/edit/[id].tsx`, открывается с `eventId` и `returnTo=event`; после сохранения/удаления — `router.back()` к форме (без `returnTo` поведение прежнее — замена на список). Удаление — прежняя очередь `deleteLocalEntity('transactions', id)` из подтверждения.
- **Документы**: «Файлы и документы» открывает существующий `mobile/app/events/[id]/documents.tsx` только для сохранённой работы (local ID допустим; новая — disabled с подсказкой). Редактор **не** сериализует `documents`/`documentFiles`, поэтому возврат/сохранение не восстанавливают удалённое вложение; на focus обновляется только счётчик «Документов: N». `documents.tsx` изменений не потребовал: принимает `{ id }`, пишет собственные мутации; переход из редактора — обычный `push` без неявного сохранения. Существующая генерация DOCX сохранена; независимый web-сценарий документов и КП не эмулировались (см. пробелы).
- **Новая работа**: до сохранения транзакции и файлы недоступны (подписи + disabled), ничего не сохраняется неявно; local ID работает через существующий outbox, повторное сохранение блокируется флагом (тест-гонка).

## Независимая проверка и исправления

После реализации выполнена отдельная сверка кода и повторный полный прогон.

- Найдено удалённое присваивание `isTransferred` в `createEventDraft`: сохранение финансов могло незаметно снять передачу коллеге. Новый тест воспроизвёл падение (ожидалось true, получено false), поле восстановлено.
- Первоначально ошибка чтения транзакций блокировала всю форму, а на возврате препятствовала получению нового клиента. Чтения разделены; ошибки клиентов и транзакций показаны независимо, передача клиента не погашается при ошибке чтения клиентов. Два новых компонентных теста сначала падали, после исправления проходят.
- Удаление транзакции ограничено текущей работой и блокирует повторную мутацию до завершения; существующий тест проверяет два подтверждения и ровно один вызов очереди. Текст подтверждения уточняет немедленное локальное удаление.
- Карандаши используют предупреждающий цвет palette, кнопки задач/транзакций/карандаш клиента имеют минимальную область 40×40. Геометрия на устройстве по-прежнему не проверена.
- Ошибочное утверждение об отсутствии мобильной генерации документов исправлено после чтения существующих экрана и endpoint. Финальный вывод проверок выше получен родительским агентом после этих правок.

## API-пробелы (не эмулировались)

- **КП/предложения и расширенный документный сценарий**: native API КП не подтверждён, web-session сценарий не эмулировался. Генерация DOCX в mobile уже существует: `POST /api/mobile/v1/events/[id]/documents/generate` использует `getRequestContext`, проверяет `allowDocuments` и tenant события/клиента/услуг. Существующий экран вызывает этот endpoint с `templateId` и `documentDate`. Но он отклоняет draft с `DRAFT_DOCUMENTS_UNAVAILABLE` (409), в отличие от нового независимого web-сценария документов. Local ID до синхронизации не является серверным ObjectId; вложения используют прежнюю файловую очередь, генерация требует синхронизированной записи и сети. Эти ограничения остаются для X; сервер и прежний экран генерации не менялись.
- **`eventFormVariant`** (`classic`/`compact`, `layouts/content/SettingsContent.js:276`) отсутствует в mobile settings DTO — переключение варианта формы как на web невозможно; поля сверены только для поддерживаемого набора.
- Общий контракт синхронизации не менялся: новые поля идут существующей мутацией `saveLocalEntity` (outbox/operationId/tombstones не тронуты).

- **Native/device-приёмка не выполнялась** (устройства нет): вид и обе темы, жесты, аппаратный Back в цепочке push→back, TalkBack, реальный offline→online, picker/share — не проверены и не заявляются.
