## Сверка с PWA и сервером

Прочитаны AGENTS, полный AI_HANDOFF, M1-T10/текущие записи ROADMAP, UI_CONVENTIONS, релевантные §4/5/AC/AD/6.3 MOBILE_PWA_PARITY, PLAN-CONTINUE и FILE_AI_IMPORT. Эталон — `components/FileImportSettings.js`, `layouts/content/ImportExportContent.js`; проверены реальные `server/fileImportService.js`, `helpers/fileImport.mjs`, `models/FileImports.js`, оба пользовательских routes и `getRequestContext.js`. Дополнительно сверены денежные ошибки `fileImportBudget.mjs`, экспорты mobile API/auth/cache/sync/темы/терминологии, установленный native SDK и matcher Expo Router.

- Используются только `/events/file-import`, `?id=<original ID>` и POST `/events/file-import/<original ID>` с actions `analyze/quote/start/refresh/stop/release`. `/worker` не вызывается. Отдельных apply или изменения распознанных fields нет.
- Бесплатная multipart-загрузка `file + note` сама не запускает анализ. Reused-файл открывает прежнее задание; адресный GET подтверждает его состояние. Список приходит от tenant-scoped API; локальный tenant не отправляется как авторизация.
- DTO и success проверяются до отображения результата. Job и event IDs требуют точного совпадения; массивы/пробелы/невалидные route params не исправляются и не вызывают API импорта. Quote ID сохраняется без нормализации.
- Тариф `allowAi` защищает серверные операции; 403 очищает доступные задания/данные формы и блокирует действия. Личный ключ не трактуется как обход тарифа.
- Анализ и импорт имеют отдельные явные подтверждения текущей сметы. Показываются provider/model, amount и estimated в копейках, доступный баланс, нехватка, анализ/общие списания и остаток резерва. Ровно достаточный баланс допускается. Для личного ключа явно показаны внешние расходы и неприменимость предела баланса Ведело. Строка фактических списаний подписана именно «с баланса Ведело»; её нули не объявляются нулевой стоимостью внешнего провайдера.
- Есть структура, правила, примеры, вопросы/варианты/«Не знаю», общий комментарий, исходники, предупреждения и пропущенные строки. Все ответы обязательны, выбор минимум одной ещё не созданной записи. Созданные/duplicate исключаются. Правки снимают локальное подтверждение, требуют нового quote. Серверный read-back quote сверяет ответы/выбор, phase/count и quote ID; UUID нового расчёта должен отличаться от прежнего.
- Ошибки сети, 400/401/402/403/404/409 и невалидные ответы не становятся success. Известные безопасные серверные причины отображаются; произвольные provider error/source/PII не копируются в сообщения ошибки.
- `stop` подтверждается отдельно и обозначает только запрос остановки. `paused/completed/refundPending` различаются. `release` возвращает остаток с адресным read-back и не удаляет задание. Смешанный результат не называется «всё импортировано».
- Работа остаётся серверным draft с `fileImportChecked=false`. Никакой автоматической проверки и локальной записи этого флага нет. После доступности, штатного sync, повторного tenant-scoped GET и проверки локального кэша открывается существующий редактор по original eventId. Его прежний переключатель «Импорт из файла проверен» сохраняется.

## Надёжность и файлы

Единый синхронный gate охватывает picker, GET, POST, upload, read-back и sync; POST/GET не перекрываются. Gate сохраняется при смене контроллера профиля, пока старый запрос не завершится. Epoch/version отзывают открытое подтверждение и поздние результаты на blur/unmount/job/session change до публикации формы, начала нового sync, invalidation и navigation.

После потери ответа POST выполняется один восстановительный адресный GET, без повтора платного запроса. Даже успешное чтение не объявляется доказательством именно этой попытки: нужен новый quote и новое подтверждение. Если read-back не удался, платные действия заблокированы до успешного чтения. Платные POST используют `skipRefresh: true`, чтобы общий auth helper также не переотправил их. Offline-запросы не попадают в outbox.

Polling действует только для `analyzing/importing`, таймер 4 секунды назначается после завершения запроса; blur/unmount/смена задания или профиля/ошибка прекращают его. Явное успешное чтение позволяет продолжить. GET активного задания может продолжить уже согласованную серверную работу; это пояснено пользователю.

Picker: один файл, `copyToCacheDirectory=true`, отмена не ошибка. MIME провайдера не считается доказательством формата: выбор доступен с любым MIME, затем проверяются расширение и размер. При отсутствующем size читается реальная метадата `File`; нулевой/неизвестный/нецелый/слишком большой размер отклоняется. Ограничены метаданные исходной кэш-копии и собственной копии, формат окончательно проверяет сервер.

Имя собственной копии — случайное `vedelo-import-*` без исходного имени. Очищаются только эта копия и подтверждённый путь Expo `Paths.cache/DocumentPicker/...` без traversal/encoded сегментов. Произвольные provider/file paths не удаляются. Cleanup выполняется при ошибке, попытке upload, замене, закрытии и unmount. Отказ удаления сохраняет предупреждение; физическая очистка не объявляется успешной. Исходник, source и draft не пишутся в SQLite, Query cache или логи.

После completed/paused используется `runSync({ fullPull: true })` и invalidation `['cached-entities','events']` / `clients`. Offline-return штатного runSync проверяется через `getSyncRunState` и не выдаётся за success. Ошибка sync имеет отдельное состояние и кнопку retry sync без повторного POST start. При открытии карточки дополнительно проверяется её наличие в локальном кэше после pull; отсутствующая/чужая/удалённая/офлайн/поздняя карточка не открывается.

## Ограничения и непроверенное

- Google-импорт и общий экспорт — следующий Q, здесь только явное пояснение без фиктивных работающих кнопок.
- Коррекция fields отсутствует в API: ответы/комментарий и последующая карточка — реальный поддержанный путь. Серверные ограничения 20 jobs / 30 дней / 100 записей не обходятся.
- Общий `parseApiError` ожидает вложенный error, а file-import HTTP failures используют строковый error и верхний code. Shared-клиент не менялся: по HTTP status показывается безопасная понятная категория; отдельный исходный код 409/400 может быть недоступен адаптеру. Верхний code при success=false envelope поддержан. Это не доказательство конкретной причины каждого 409.
- Серверный DTO не содержит request identity, поэтому восстановительный GET доказывает только текущее состояние задания. Не обещается связь этого статуса с потерянной попыткой.
- Синхронизация, уже начатая до blur, выполняется существующим shared engine; native-адаптер не меняет его lifecycle и не отменяет внутренние шаги. Поздний результат не запускает новые invalidation/navigation из закрытой формы.
- В текущей среде `shutil.which('adb')` и `shutil.which('java')` вернули `None`.
- Компонентные проверки двух тем, доступных labels, длинного текста и состояний не являются pixel-perfect/device-приёмкой. Реальный Android picker/Back, узкий экран, увеличенный шрифт и TalkBack не проверены на устройстве. HTML gates к native не применялись.
- Настоящие two-tenant HTTP/Bearer/тарифные прогоны, реальное списание, внешний ИИ и production cron не запускались. Проверены mocks и прочитан tenant-scoped контракт, а не реальная доставка/биллинг. EAS, production, env и credentials не использовались.
- M1-T10 и весь mobile/PWA parity не объявляются завершёнными.
