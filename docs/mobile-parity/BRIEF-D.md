# Задание D — оболочка навигации: нижняя панель, шторка «Меню», центральное «+» (этапы F, G, H плана)

Репозиторий: `~/projects/ArtistCRM`, ветка `codex`. Прочитай `AGENTS.md`, затем `docs/MOBILE_PWA_PARITY.md` — §3 (карта навигации), §4.3 (геометрия нижней панели и меню), §6.1, §6.2 этапы **F**, **G**, **H**.

Предыдущие шаги уже в репозитории: этапы B/C (удаление developer-функций) и D/E из BRIEF-C (токены, тема, примитивы) — используй их, не дублируй.

## Цель захода

Мобильная навигация Android должна повторять нижнюю панель PWA: **Важное / работы / [+] / Клиенты / Меню**, с подменю раздела работ, шторкой всех разделов и центральным меню создания.

## F — нижняя оболочка

Файлы: `mobile/app/(tabs)/_layout.tsx`, новый `mobile/src/features/navigation/MobileBottomBar.tsx`, `mobile/app/(tabs)/more.tsx` как совместимый route.

- Ровно пять слотов в порядке §3. «Финансы», «Задачи», «Профиль» остаются адресуемыми маршрутами, но **не** видимыми вкладками.
- «Важное» — переход на переработанный экран (в этом заходе содержимое ещё текущее, семантика — этап J); бейдж просроченных задач, а не сумма всех метрик.
- «Работы» (термин из resolver) — тап открывает подменю «Предстоящие / Прошедшие», выбор задаёт scope и открывает список.
- «+» — центральная кнопка-действие (FAB 50, marginTop −16, radius 999, `navigationBackground`/`fabForeground` из §4.2), не экран.
- «Меню» — открывает шторку (этап G), активное состояние определяется текущим разделом.
- Геометрия: min-height 60 + safe area, иконки 30, подписи 10/1.2, gap 3, padding 6×2; панель занимает **своё место** в layout и не перекрывает последнюю карточку.
- Открыта одновременно только одна панель; повторный тап, тап по затемнению и смена маршрута закрывают её; Android Back закрывает overlay, а не уводит назад сразу.
- Не терять scroll position и фильтры при временном открытии панели.

## G — пользовательское «Меню»

Новые: `mobile/src/features/navigation/menu.ts`, `MenuSheet.tsx`, `EventsSubmenu.tsx`; править `mobile/app/(tabs)/more.tsx`, `mobile/app/more/[section].tsx`.

- Каталог только пользовательских путей. Порядок §3: «История действий» → «Статистика» → «Транзакции» → «Звонки» → «Настройки» (внутри: Общие настройки → Мои услуги → Интеграции → Импорт и экспорт → Документы → Списки → Уведомления → Реферальная система) → «Обратная связь». Пустые группы не показывать.
- Группа из 2+ пунктов — аккордеон, по умолчанию закрыт; одиночный пункт — сразу строка. Строка min-height 42, radius 9, gap 10, paddingX 12, шрифт 13/600; вложенные с paddingLeft 34; sheet radius 16, padding 6, боковые 8. Прокрутка шторки ограничена доступной высотой над панелью.
- Бейдж непрочитанной поддержки — `99+`, а не `!`.
- Профиль и тариф не входят в `pages`: сохранить отдельные личные входы (компактная верхняя часть шторки или служебная область), ссылку на `/sync` оставить.
- **Whitelist секций**: неизвестный `section` в `/more/[section]` больше не должен проваливаться в «Списки». Прямые административные адреса (`/more/users`, `/more/tariffs` и т.п.) должны давать понятное «раздел недоступен», а не generic-экран.
- Старый `/(tabs)/more` открывает тот же каталог — не второй расходящийся список.

## H — центральное меню создания

Новый `mobile/src/features/navigation/CreateWorkItemMenu.tsx`; править `mobile/app/events/edit/[id].tsx`, при необходимости `mobile/src/features/events/VoiceDraftSection.tsx` / `voiceDraft.ts`.

- Пункты как в PWA `useEventCreateMenu`: «Заявка» (`draft`), «Подтверждено» (`active`), при доступном AI-тарифе — «Голосом», «Свободным текстом».
- Редактор сейчас знает только `id/clientId/cloneId`: добавить валидируемый параметр начального статуса (`draft`/`active`), принимая **только** эти два значения; произвольный статус из URL игнорировать. Одно изменение tab bar — недостаточно, меню должно реально доносить статус до формы.
- Создаётся именно работа, а не клиент/транзакция. AI-пункты используют существующие `VoiceDraftSection`/`voiceDraft.ts`, проверку тарифа и сети, явное применение результата; без сети ручные варианты доступны.
- Данные клиента/черновика не вкладывать в deep-link URL.

## Жёсткие границы

- Меняются только файлы внутри `mobile/`. Web-код (`app/`, `server/`, `layouts/`, `helpers/`, `components/`, `models/`, `schemas/`) не трогать.
- **Не редактировать** `mobile/src/shared/storage/**`, `mobile/src/shared/sync/**`, схему SQLCipher, outbox, ключи кэша, `operationId`, tombstones, файловые очереди.
- Не менять package ID, схемы deep link (`vedelo://`, `artistcrm://`), `app.json`, `eas.json`, EAS-профили, push-настройки в `mobile/app/_layout.tsx`.
- Не менять серверный код и мобильный API-контракт.
- `mobile/src/shared/notifications/index.ts` (неотслеживаемый, чужая параллельная работа) **не трогать**.
- В рабочей копии есть чужие незакоммиченные изменения — не откатывать, не удалять, не коммитить.
- Не переписывать содержимое экранов «Важное», списков и карточек — это следующие этапы. Здесь только оболочка и каталог.
