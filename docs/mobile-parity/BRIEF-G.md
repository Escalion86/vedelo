## N — просмотр работы

Файлы: `mobile/app/events/[id].tsx`, новые `mobile/src/features/events/EventFinanceSummary.tsx`, `EventDetailActions.tsx`.

- Порядок блоков по §5.7: notice импорта/галерея при наличии → теги/действия → адрес, дата создания и статус → начало/окончание/длительность → описание → предупреждение об обязательствах → финансы для не-`draft` (договор, получено, расходы, итог) → подробности → контакты → задачи → навигация.
- Корректные KPI: обязательства не входят в фактические доходы/расходы до смены метода оплаты; контроль договора учитывает только клиентские оплаты (`deposit`/`final_payment` и legacy-аналоги), чаевые и реферальные выплаты остаток не уменьшают.
- Недоступные действия объясняют причину явно (например, оплата только для `active`), а не исчезают молча; переходы ведут в нужную секцию редактора, к документам и истории.
- Серверные сценарии, которых нет в мобильном API (коммерческие предложения, адресные подсказки), **не эмулировать**.
- Проверить `draft`/`active`/`closed`/`canceled`, offline и локальный (несинхронизированный) ID.

## O — редактор: общие данные и каркас трёх секций

Файлы: `mobile/app/events/edit/[id].tsx`, новые `mobile/src/features/events/EventGeneralSection.tsx`, `mobile/src/shared/domain/eventForm.ts` и его тесты.

- Ввести каркас трёх вкладок как в PWA (§5.7): **Общие → Клиент и контакты → Финансы и Документы**. В этом заходе полностью реализуется вкладка «Общие», для двух других — каркас и корректная передача общего draft (их содержимое — следующий заход).
- Общий draft: переключение вкладок, Back и клавиатура **не теряют** введённое; mutation запускается только по явному сохранению; ошибка сохранения не стирает форму.
- «Общие»: тип и услуги, даты (начало/окончание), локация (город/улица/дом/подъезд/этаж/офис/комментарий — как сейчас), описание, условная передача коллеге и признак проверки импорта, дата заявки, статус.
- Даты: либо нативные контролы, либо валидируемый fallback без потери часового пояса; значения формата `YYYY-MM-DD` разбирать в локальной зоне (как уже сделано в календаре).
- Не переносить произвольные web-only поля. HTML rich text не выводить в native сырыми тегами.
- Начальный статус из параметров (`draft`/`active`) уже валидируется навигацией — сохранить это поведение.

## Жёсткие границы

- Меняются только файлы внутри `mobile/`. Web-код (`app/`, `server/`, `layouts/`, `helpers/`, `components/`, `models/`, `schemas/`) не трогать.
- **Не редактировать** `mobile/src/shared/storage/**` и `mobile/src/shared/sync/**`: схема SQLCipher, outbox, ключи кэша, `operationId`, tombstones, файловые очереди остаются как есть. Сохранение работы идёт существующими мутациями/outbox, прямой POST вместо очереди запрещён.
- Не менять package ID, схемы deep link, `app.json`, `eas.json`, push-настройки, серверный код и мобильный API-контракт.
- `mobile/src/shared/notifications/index.ts` (неотслеживаемый, чужая параллельная работа) **не трогать**.
- Чужие незакоммиченные изменения не откатывать, не удалять, не коммитить.
- Списки клиентов и транзакций, документы, другие разделы — следующие этапы, здесь не переписывать.
