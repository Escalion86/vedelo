# Задание G — этапы N и O

Дата: 01.10.2026. Изменения на диске, без коммита. Программная реализация N/O выполнена; визуальная приёмка на Android остаётся непроверенной.

## N: просмотр работы

- `mobile/app/events/[id].tsx` перестроен в порядке §5.7: проверка импорта и галерея при наличии → признаки/действия → адрес, создание/дата заявки и статус → начало/окончание/длительность → описание → обязательства → финансовая сводка для не-draft → подробности → контакты → задачи → навигация.
- `EventFinanceSummary.tsx` показывает договор, фактические доходы, расходы, итог и отдельно оплату/остаток/переплату договора. `eventDetail.ts` содержит проверяемые расчёты и причины недоступности действий.
- Обязательства не входят в фактические доходы/расходы до изменения метода оплаты. Только `deposit`, `advance`, `final_payment`, `client_payment` типа income уменьшают остаток договора. Чаевые и рекомендации входят в общий доход, но не в клиентскую оплату договора. Учитываются только транзакции текущей работы.
- `EventDetailActions.tsx`: переходы в выбранную секцию редактора, документы, историю, переписки и клонирование. Оплата доступна только для active; для остальных статусов видна причина. У local ID история/переписки недоступны до синхронизации; без сети переписки недоступны, история серверной записи может использовать существующий cache.
- Чтение переведено на существующий `useCachedEntities`, с обновлением при возврате к экрану. Загрузка, отсутствие записи и ошибка чтения различаются. Ошибки чтения финансов не подменяются нулевыми KPI. Сбой сохранения задачи показан пользователю; повторный одновременный вызов блокируется.
- Существующий `QuickContacts`, семантические статусы, Notice и palette используются для светлой/тёмной темы. HTML описаний преобразуется в текст. Галерея использует существующие HTTPS-ссылки; новые изображения и бинарные ресурсы не создаются.

## O: общий draft и вкладка «Общие»

- Три вкладки: «Общие», «Клиент и контакты», «Финансы и Документы». Один `EventDraft` в родительском экране хранит поля, услуги, контакты и задачи. URL-параметры считываются при открытии и не перезаписывают введённое при rerender.
- `EventGeneralSection.tsx`: тип и услуги, даты, город/улица/дом/подъезд/этаж/офис/комментарий, описание, передача коллеге, проверка импорта, дата заявки и статус. Передача показывается при `custom.showColleagueTransferFields === true` или для уже переданной работы; коллега выбирается из существующих локальных клиентов.
- Поля двух следующих вкладок сохранены из прежнего редактора и подключены к общему draft. Их полная переработка, поиск/создание контактов, фильтрация выполненных задач, финансовый комментарий, договорность, транзакции и сценарий документов из несохранённой формы остаются этапам P/Q. Наличие каркаса не объявляется завершением этих этапов.
- Mutation вызывается только кнопкой «Сохранить»; используются прежние `saveLocalEntity`/outbox. При ошибке форма остаётся на месте. Загрузка существующей записи должна завершиться до появления формы и кнопки сохранения.
- Back при изменённой форме предлагает остаться или явно выйти без сохранения. Отказ от выхода сохраняет draft. Закрытие клавиатуры и смена вкладок не сохраняют и не очищают форму; `Screen` получил опциональный `keyboardShouldPersistTaps`, включённый для редактора. Выход после успешного сохранения разрешён отдельно.
- Исходная валидация initialStatus сохраняется: только draft/active для новой работы; URL не меняет статус редактируемой записи, копия создаётся как draft.

## Правила дат и сериализации

- Fallback принимает `YYYY-MM-DD` (00:00 местного времени устройства) и `YYYY-MM-DD HH:mm` / `YYYY-MM-DDTHH:mm`; невозможные даты/время отклоняются. ISO со смещением в поле ввода не принимается: существующий ISO сначала отображается в местной зоне.
- Проверяется порядок начала/окончания, дата заявки, срок задатка и даты задач. Изменённое время сериализуется в ISO; неизменённые даты сохраняют исходные секунды, миллисекунды и смещение.
- HTML описания показывается как текст; если описание не менялось, исходный HTML сохраняется при записи других полей. Это также учитывается для существующих задач.
- Сериализация использует явный список полей: tenant/role/операторы Mongo/служебные поля из draft не копируются. Неизвестные услуги отфильтрованы, дубликаты услуг удалены, новые неизвестные ссылки на клиентов отклоняются; существующие ссылки, в том числе архивные услуги и local ID, сохраняются.
- Отрицательные/нечисловые суммы, неизвестный статус, передача без коллеги, повторяющиеся контакты не проходят проверку. После изменения основной локации старые координаты и ссылки маршрута очищаются.

## Границы и риски

- Изменён только код/тесты внутри `mobile/` и этот отдельно запрошенный отчёт. Web/API, storage, sync, notifications, package ID, deep links, Expo/EAS/push-конфигурация не изменены.
- Исходные чужие изменения, включая `mobile/package-lock.json` и неотслеживаемый `notifications/index.ts`, сохранены; коммит не создан.
- M1-T10 остаётся в работе: он включает этапы после N/O и device QA. Пункт roadmap не закрывается; root package.json, ROADMAP и план не изменены в силу границ брифа. Прогресс N/O зафиксирован здесь.
- Серверные сценарии предложений и адресных подсказок не эмулируются. Проверки закрытия на сервере не заменяются выдуманным мобильным API. Существующие tenant-проверки и sync-контракт не изменены; тест проверяет, что чужой новый client ID/tenant-поля не уходят из draft в payload.
- `adb` отсутствует. На устройстве не проверены ширины 320/360/390, крупный шрифт, TalkBack, реальные жесты Back/клавиатура, light/dark screenshots, загрузка изображений и реальный offline→online sync. Jest проверяет поведение компонентов/проекций, но не заменяет эту приёмку.
- Draft живёт в открытом экране. Явный выход без сохранения и завершение процесса не являются автосохранением; persisted storage намеренно не добавлен. Удалённые изображения требуют сети либо системного кэша изображений.
