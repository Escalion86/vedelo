## Осталось

По `docs/MOBILE_PWA_PARITY.md` §6.2 не выполнены:

- **P, Q** — вкладки редактора «Клиент и контакты» и «Финансы и Документы»;
- **R, S** — список и карточка/форма клиентов;
- **T, U** — список и редактор транзакций;
- **V, W** — услуги, списки и общие настройки;
- **X** — документы; **Y** — звонки и переписки; **Z** — интеграции; **AA** — статистика и рефералы; **AB** — история;
- **AC–AF** — импорт/экспорт (нужна сверка API, отдельный контрактный пробел);
- **AG–AJ** — профиль/тариф, уведомления и support-presentation, auth/onboarding/sync, включение тёмной темы;
- **AK** — интеграционный приёмочный прогон.

Отдельно открыто:

- секция неотвеченных сообщений на «Важном» (этап **K**) — требует сверки user-scoped API переписок;
- визуальная приёмка на устройстве: на Orange Pi нет `adb`/Java, нужна EAS preview-сборка и телефон.

## Как продолжать

1. Задание на этап — файл `docs/mobile-parity/BRIEF-<буква>.md` по образцу BRIEF-E/F/G: границы захода, что не трогать, обязательные проверки, путь к отчёту `docs/mobile-parity/REPORT-<буква>.md`.
2. Запуск Codex Astra — **не фоном Hermes** (процесс убивается вместе с сессией), а отвязанным user-юнитом systemd:

```bash
export XDG_RUNTIME_DIR=/run/user/1000
systemd-run --user --unit=astra-stage-<x> --collect \
  --property=StandardOutput=file:/tmp/astra-<x>.log \
  --property=StandardError=file:/tmp/astra-<x>.log \
  /home/aleksei/.hermes/cache/scratch/astra-stage-<x>.sh
systemctl --user is-active astra-stage-<x>
```

3. После завершения: глазами проверить диф, прогнать `npm run typecheck` и `npm test`, закоммитить **только** файлы этапа (в рабочей копии есть чужие незакоммиченные изменения — их не трогать), затем запускать следующий.
