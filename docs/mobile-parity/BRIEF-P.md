## Контракт, который уже подтверждён родителем
- Bearer поддержан пользовательскими endpoints /events/file-import и /events/file-import/<id> (base URL api уже содержит /api); /worker НИКОГДА не вызывать, это служебный cron.
- POST multipart file + note: бесплатное извлечение/оценка; GET список; GET ?id=ObjectId: точное состояние, может продолжить уже авторизованную работу.
- POST action: analyze/quote/start/refresh/stop/release. НЕТ отдельного apply, нет прямого редактирования распознанных fields в API. quote принимает ответы на вопросы и comment + selectedIds, исключает созданные/duplicate; analyze/start требуют точного текущего quoteId и правильной phase. stop только просит остановку, не означает остановлен; release — возврат остатка, не удаление задания.
- Все операции require allowAi, личный ключ не обходит тариф; баланс/настройка провайдера проверяются сервером. Файл до 5*1024*1024 байт, один XLSX/CSV/TXT/DOCX. 20 сохранённых jobs, 30 дней, 100 записей. Локальное MIME не доказательство формата, окончательная проверка серверная.
- serialize: id/fileName/status/warnings/note/analysis/ignored/records/selectedIds/answers/quote/error/balanceRub/actualCostRub/analysisCostRub/reservedRub/refundPending/expiresAt. Record source/title/id/status/error/eventId/warnings; НЕТ fields в пользовательском ответе. Quote id/phase/count/amountKopecks/estimatedKopecks/markup/provider/model/createdAt.
- statuses job uploaded/analyzing/review/quoted/importing/paused/completed/failed. Record pending/processing/created/duplicate/possible_duplicate/needs_attention/error. Работа создаётся сервером draft importedFromFile=true/fileImportChecked=false; успешный импорт не означает проверку.

## Требования
1. Пользовательский route «Импорт и экспорт» с поддержанным файловым разделом. Google и общий экспорт ещё не реализованы (следующий Q): не изображать работающие кнопки/фиктивные возможности. Обе темы на существующих компонентах/useTheme, компактные три этапа/Notice/поля/прогресс, доступные labels/targets, narrow/long names. Формы в functional components.
2. Native picker expo-document-picker: single, cancellation не ошибка, copyToCacheDirectory=true. Проверить расширение и реальный размер File если size отсутствует; не принимать нулевой/слишком большой/unsupported файл, не хранить исходник в SQLite/query cache/логах. React Native multipart append {uri,name,type} через api.upload, не JSON. Cleanup собственной временной копии после попытки/замены/закрытия/unmount; не удалять произвольный путь провайдера. Отказ cleanup обрабатывать и не объявлять физическое удаление успешным.
3. Список своих jobs с loading/empty/error/retry/403, открыть сохранённый/повторно загруженный reused job и продолжить с реальными состояниями. Валидировать success/envelope/DTO, оригинальные ID/quote без молчаливого trim/исправления. Не делать запрос по invalid/array route param. Exact job ID ответа обязателен для адресных GET/POST. Не доверять локальному tenantId для авторизации.
4. Платный анализ только после явного подтверждения текущей сметы: показать модель/провайдер, предел анализа, доступный баланс/нехватку, расходы личного ключа не назвать нулевыми. Quote_changed/403/expired/AI_unavailable/balance — безопасная понятная ошибка, не сырые provider errors/source/PII. Бесплатная загрузка не запускает analyze автоматически.
5. Проверка структуры: summary/rules/examples/questions/options/источники/warnings/ignored lines. Ответы/общий comment и выбор ещё не созданных записей, минимум одна и ответы обязательны. Правка ответов/selection после quote инвалидирует локальное подтверждение; новый quote явно. Сервер не принимает редактирование fields: не делать фиктивный редактор даты/суммы, честно назвать коррекцию ответами/комментарием и последующую карточку.
6. Смета импорта: amount/estimated в копейках, анализ actual cost/reserved, ровно достаточный баланс годится; при личном ключе предупредить о внешних расходах. Запуск только подтверждённый current quote import после quote selected answers read-back. Старый quoteId/открытый диалог не применяются после изменения draft/job/session. Без автоповтора analyze/start после сетевой неопределённости. При потере ответа восстановить exact GET job; если исход неизвестен — блокировать платную повторную попытку до успешного чтения и нового явного подтверждения. Не объявлять GET статус доказательством именно этой попытки, если нет request identity; честный результат.
7. Poll only active analyzing/importing, single-flight с таймером после ответа, no overlapping POST/GET, остановка на blur/unmount/job/session/403. Poll ничего платного не запускает; server GET может продолжить уже согласованную работу, это пояснить. Неисправимые/невалидные ответы прекращают polling и позволяют retry чтения. Сеть/offline не ставит платные действия в outbox. Double taps/parallel requests guards синхронные. Late upload/action/GET после blur/профиля/job change не обновляет новую форму и не провоцирует navigation/cache/sync side effects.
8. Progress: counts по статусам/реальные warnings/errors, stop с подтверждением и read-back, paused/completed/refundPending различать; release остатка явный без фиктивного удаления. Возобновление через коррекцию/quote/start, не повторять successful created/duplicate. Не писать «все импортировано», если есть skipped/needs_attention/errors.
9. После серверного завершения штатный runSync + invalidate cached entities events/clients; состояние «сервер завершил, локальная синхронизация не выполнена» с отдельным retry sync, не повтор POST start. Переход к созданной карточке — по реальному original eventId, с GET tenant-scoped доступности/точным ID и sync; чужой/deleted/offline/late не открывать. Не выставлять fileImportChecked локально; существующий редактор пользователя.
10. Draft пользовательских ответов не затирать poll/refresh при ошибках. Предупреждение несохранённых правок при закрытии/смене job, не кэшировать персональный source/draft. Запрос неуспешен => UI не показывает success. Результат state-changing POST подтверждать адресным GET, отказ read-back не повторяет mutation автоматически.
