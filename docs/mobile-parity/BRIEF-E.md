## I — чистые селекторы (без UI)

Новый `mobile/src/features/attention/selectors.ts` и `selectors.test.ts` (при необходимости — только уже существующие поля в `mobile/src/shared/domain/types.ts`).

- Проекции из локального кэша мероприятий: просрочено, сегодня, завтра; задатки, ожидающие получения (в т.ч. просроченные); незакрытые прошедшие; работы на 3 дня; значимые даты клиентов.
- Правила «выполнено» ровно как в PWA (§5.6, п. 4): выполненные идут после невыполненных и не увеличивают pending-count; done с сегодняшней/завтрашней датой остаётся в своей секции; done с **просроченной** датой считается выполненным только сегодня; без срока или со сроком позже — только выполненные сегодня, в секции «Сегодня».
- Источник задач один — `additionalEvents[]`. Никаких новых независимых «баз задач», новых persisted-статусов и полей в storage.
- Время передаётся параметром (`now`) — фиксированное в тестах. Обязательные тесты: границы суток, работа без даты, doneAt сегодня, оплаченный задаток, canceled/closed, многодневная работа (`eventDate`/`dateEnd`).

## J — экран «Важное» и действия задач

Файлы: `mobile/app/(tabs)/index.tsx`, `mobile/app/(tabs)/tasks.tsx`, новые `mobile/src/features/attention/AttentionScreen.tsx`, `TaskCard.tsx`.

- Порядок блоков — строго по §5.6: summary-лента ненулевых счётчиков (просрочено / сегодня / завтра / сообщения / не закрыто / даты клиентов) → условное «Закрытие мероприятий» → «Просрочено / Сегодня / Завтра» → работы на 3 дня → значимые даты клиентов; sync-секция при наличии очереди.
- Summary-лента **прокручивает к секции**, а не открывает отдельный экран. «Закрытие мероприятий» — только навигация к прошедшим с фильтром незакрытых; массового закрытия одним нажатием не делать.
- Карточка задачи: заголовок и дата, контекст работы и адрес, отметка/отмена выполнения, редактирование/удаление, быстрый перенос. Действия использовать **сегментные**, как в PWA, а не всегда одинаковые `+1/+3`.
- Действия задач обязаны идти через существующие offline-мутации и outbox (`mobile/src/shared/storage/mutations.ts`, доменные `taskActions`), как это делает обработчик push-действий. Прямой POST вместо очереди — запрещён.
- Работы на 3 дня показывать существующим `MobileEventCard`, а не мини-карточкой-календариком из старого макета.
- Пустые состояния и ошибки — по §5.5: «ещё нет данных» (создание), «фильтр ничего не нашёл» (сброс), «ошибка чтения» (повтор) — это три разных состояния, а не пустой список.
- Из обзора убрать блок «финансы месяца» (он не часть «Важного»). Существующий sync-статус и подписка на `useSyncRunState` сохраняются; web-очередь не копировать — native показывает своё, более полное состояние.
- Если в обзоре записей больше 12 — дать предсказуемый доступ к остальным (кнопка «показать все» или прокрутка без потери задач); зафиксируй решение как native-адаптацию.
- `tasks.tsx` становится совместимым входом в ту же реализацию, а не второй независимой версией экрана.

- Меняются только файлы внутри `mobile/`. Web-код (`app/`, `server/`, `layouts/`, `helpers/`, `components/`, `models/`, `schemas/`) не трогать.
