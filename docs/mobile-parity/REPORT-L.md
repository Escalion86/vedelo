## Реализовано

- Иерархия «Шаблоны документов / Документы записи / Локальные копии и очередь», отдельные счётчики и состояния. Ошибка чтения не превращается в успешный пустой список. Ошибка шаблонов не скрывает локальные вложения; ошибка локальных файлов не скрывает документы записи и доступные шаблоны.
- ThemeProvider/palette, Notice, CompactField, семантические кнопки. Длинные названия переносятся в гибкой центральной колонке; отдельные действия имеют область нажатия 40 px. Подписанные URL и raw lastError не выводятся в строках.
- Шаблоны: DOCX до 5 МБ, проверка расширения **или** DOCX MIME по действующему validator; name до 160, customTypeName до 120, только текущие типы. Название своего типа необязательно, как в API/PWA; при другом type оно не отправляется. Отмена picker не меняет draft и ничего не сохраняет. Ошибка/403/404/missing существующего шаблона не открывает пустой редактор; есть повтор чтения.
- Повторные picker/save/delete/share/retry блокируются до завершения действия. Несохранённый выход и удаление подтверждаются; ошибка сохранения оставляет ввод. Если upload ответил корректными метаданными, но контрольный GET не подтвердил результат, доступен отдельный повтор **чтения**, без нового upload. Удаление проверяется GET до выхода из редактора.
- Перед действиями перечитываются актуальная сущность и документ/локальный файл. Проверяются `_id`, document ID, local file ID/URI и entityType/entityId; также владелец связанного локального файла в общем разделе Documents. Старый ответ route/unmount не меняет новый экран и не вызывает поздний upsert/native share. Старое подтверждение удаления не действует на новый маршрут.
- Документы читаются из `documents[]`; `documentFiles` отображается совместимо без дублирования канонических ID/URL. Снятие legacy-связи использует существующую saveLocalEntity и узкий patch обоих массивов при необходимости; соседние документы и прочие поля сохраняются. Миграции или переименование events не выполнялись.
- Три разных удаления: зашифрованная локальная копия/строка очереди; снятие legacy/canonical URL-связи через outbox; физическое удаление private файла через files DELETE. Подтверждение описывает точный смысл. Удаление локальной копии не удаляет серверный документ. Локальное снятие ссылки отмечается как queued, а серверное удаление получает подтверждение только после read-back.
- Upload использует encryptAndQueueFile → runSync, failed retry — существующий retryFileQueueNow с точными ID. Отображаются реальные pending/uploading/failed/synced, без фиктивных процентов. Raw инфраструктурные ошибки заменены безопасной инструкцией. Автоматического объявления успешной загрузки по одному завершению runSync нет.
- Расшифрованные и скачанные временные файлы очищаются в finally, включая ошибку share/записи скачанного файла. Ошибка cleanup не подменяет исходную ошибку. Private URL используется только для открытия/поделиться, не записывается UI в кэш и не логируется.
- Генерация: строгая календарная дата ГГГГ-ММ-ДД; текущий templateId повторно проверяется по списку; только серверный event ID, non-draft и синхронизированные данные. Проверяются success, event ID, новый document ID и его наличие в ответе; затем отдельный GET работы подтверждает именно этот document ID до upsert/успеха. Неподтверждённый результат позволяет повторять GET. После потери ответа наличие произвольного нового документа не выдаётся за доказательство результата POST. Новое создание требует отдельного подтверждения риска дубликата и следующего явного нажатия; автоматического повторного POST нет. Явный отказ 4xx не считается успехом.

## Фактический API и ограничения

- Шаблоны: GET/POST/DELETE `/mobile/v1/document-templates`; POST возвращает метаданные шаблона, DELETE — `{id}`. GET `/mobile/v1/document-templates/[id]` возвращает DOCX bytes, используется существующий bearer download и временный файл для native share. У новых шаблонов ID выдаёт сервер. После потери ответа создания ручный повтор upload может создать второй шаблон: API не предоставляет idempotency key. UI не повторяет upload автоматически и сохраняет ввод с указанием проверить список.
- Legacy DOCX fallback строится сервером из старых contract/act полей. Если после DELETE такой fallback снова появился в GET, UI не объявляет успешное удаление. Очистка этих старых настроек не входит в разрешённые mobile UI изменения.
- Вложения: POST/DELETE `/mobile/v1/{events|clients}/[id]/files`; POST `/files/access-url`; GET сущности `/mobile/v1/{events|clients}/[id]` для read-back. Tenant/ownership/allowDocuments проверяют существующие серверные обработчики. Клиентского выдуманного флага доступа нет; 403 показывается безопасно, а queued файл не считается загруженным.
- Генерация: POST `/mobile/v1/events/[id]/documents/generate` принимает только templateId/documentDate, возвращает `{document,event}`. В отличие от web, запрещает draft и не поддерживает requestId/preview/источник из КП. Независимые web документы, связь чека с оплатой, расширенное редактирование метаданных, КП и web preview не эмулируются.
- Существующая инфраструктура умеет перепривязать файлы local event после remap ID; UI сохраняет такой upload в штатную очередь. Ограничение I для local клиента сохранено: сначала синхронизация клиента. После remap старый local route может перестать находить запись — нужно открыть её серверную карточку; UI не подставляет другую сущность в старый маршрут.
- Прямые серверные delete/generate не перетирают найденные несинхронизированные изменения кэша: результат можно перечитать после завершения синхронизации. Подтверждённый GET объединяется с текущей записью, сохраняя поля, отсутствующие в ответе.
- Проверки ответов перед **UI-управляемым** upsert добавлены. Собственные upsert/повторы общего file sync, внутренний auth refresh и уже начавшийся runSync не изменены и не могут отменяться этим экраном. Их поведение не выдаётся за новое инфраструктурное исправление.
- Для path-only legacy документа без HTTP/HTTPS URL/storageKey нет нового придуманного download endpoint: открытие сообщает безопасную ошибку. Существующие URL-вложения и private storageKey поддерживаются.
- Cleanup — best effort через существующие функции; поведение Android после process death и фактическое удаление временных файлов на устройстве не доказаны Jest.
