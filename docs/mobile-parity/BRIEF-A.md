# Задание A (этап «Разведка и план») — паритет Android-приложения и мобильной PWA

Ты — инженер проекта «Ведело» (бывший ArtistCRM). Репозиторий: этот каталог (`~/projects/ArtistCRM`, ветка `codex`).
Прочитай `AGENTS.md` и `docs/AI_HANDOFF.md` перед работой.

## Цель проекта (не этапа)

Android-приложение (`mobile/`, Expo + React Native + expo-router) должно быть **максимально похоже на мобильную версию PWA**
(`vedelo.ru`, Next.js, кабинет `/cabinet/*`) — по навигации, составу разделов, визуальному языку и поведению экранов.
В приложении остаётся **только функционал конечного пользователя**: всё, что доступно роли `dev` (разработчик/владелец платформы)
и администрированию платформы, из Android-приложения убирается. Отдельное приложение для разработчика делается позже.

## Что нужно сделать В ЭТОМ ЭТАПЕ

Только анализ и письменный план. **Никаких изменений в коде, кроме одного нового документа.**
Артефакт: `docs/MOBILE_PWA_PARITY.md` (создать). Затем один коммит только с этим файлом.

## Обязательная фактура (читать именно это, ссылаться на пути и строки)

Сторона PWA (источник правды по UX/визуалу):

- `components/MobileBottomNav.js` — нижняя навигация телефона: Важное / Мероприятия / [+] / Клиенты / Меню.
- `helpers/constants.js` — `pages` (href, name, group, accessRoles) и `pagesGroups` — полный состав разделов и групп меню.
- `helpers/pageAccess.js` — правило доступа по роли.
- `layouts/content/contentsMap.js` — карта страниц кабинета.
- `layouts/content/AttentionContent.js` — страница «Важное».
- `layouts/content/EventsContent.js`, `layouts/cards/EventCard.js` — список и карточка работы.
- `layouts/content/ClientsContent.js`, `layouts/content/TransactionsContent.js` — клиенты и финансы.
- `layouts/modals/modalsFunc/eventFunc.js`, `eventViewFunc.js` — формы и просмотр работы.
- `app/globals.css` — токены кабинета (`--ui-primary` и т.д., светлая и тёмная темы) и мобильные классы (`mobile-bottomnav*`, `ui-surface-card`).
- `docs/mockups/*.html` и `docs/mockups/*.png` — утверждённые макеты мобильной PWA (нижняя навигация, подменю, страница «Важное», переключатель сегментов).
- `design-qa.md` — зафиксированная анатомия мобильных карточек и фильтров (высоты контролов, разделители, порядок строк).
- `docs/MOBILE_APP_ARCHITECTURE.md` — текущая архитектура Android-клиента.

Сторона Android:

- `mobile/app/**` — маршруты (вкладки `mobile/app/(tabs)/*`, экраны `mobile/app/**`).
- `mobile/src/shared/ui/theme.ts`, `mobile/src/shared/ui/components.tsx` — текущая дизайн-система.
- `mobile/src/features/**` — доменные секции (карточка мероприятия, календарь, услуги, списки, интеграции, поддержка, биллинг).
- `mobile/src/shared/domain/workItemTerminology.ts`, `mobile/src/shared/hooks/**` — терминология «мероприятия/заказы».
- `mobile/src/shared/storage/**`, `mobile/src/shared/sync/**` — offline-ядро (SQLCipher, outbox, конфликты). **Не переписывать.**

## Содержание документа `docs/MOBILE_PWA_PARITY.md`

1. **Краткое резюме**: чем Android сейчас принципиально отличается от мобильной PWA (не более 10 пунктов, каждый с ссылкой на файл).
2. **Карта разделов**: таблица «раздел PWA (`pages`) → экран Android → статус». Статусы: `есть и совпадает`, `есть, но отличается`,
   `отсутствует`, `developer-only (удалить из приложения)`. Для developer-only отдельная колонка с обоснованием (роль/`accessRoles`).
3. **Карта навигации**: текущие вкладки Android vs слоты нижней панели PWA; что делать с `Главная`/`Финансы`/`Ещё`; как переносится
   шторка «Меню» с аккордеон-группами; где живёт кнопка «+» и меню создания.
4. **Дизайн-контракт для Android**: точная таблица соответствия токенов (web `--ui-*` и палитра кабинета → `colors` в `mobile/src/shared/ui/theme.ts`),
   типографика (размеры/веса/ограничения), радиусы, отступы, состояния (default/hover-аналог/pressed/disabled), семантика статусов.
   Значения брать из кода PWA и `design-qa.md`, не выдумывать.
5. **Анатомия ключевых компонентов**: карточка работы, карточка клиента, карточка транзакции, строка фильтров/сегментов,
   строка поиска, заголовок страницы, пустые состояния, плитки «Важное». Описать состав и порядок блоков по данным PWA.
6. **План работ по этапам** (пронумерованные этапы B, C, D, …): для каждого — цель, конкретные файлы Android, критерии приёмки и способ проверки.
   Требования к этапам: каждый этап самостоятельно проверяем (`cd mobile && npm run typecheck`, `npm test`), не длиннее одного рабочего захода,
   не ломает offline-ядро, не трогает web-код.
7. **Список удаляемого developer-функционала**: точные экраны/блоки/поля Android с путями, и что происходит с навигацией после удаления
   (например, убрать ветку роли `dev`, а не прятать).
8. **Риски и открытые вопросы**: что нельзя проверить на Orange Pi (нет adb/Java, сборка — через EAS), где нужен визуальный QA на устройстве.

## Жёсткие ограничения

- Никаких изменений в `app/`, `components/`, `layouts/`, `helpers/`, `server/`, `models/`, `schemas/` — web-часть только читается.
- Не менять package ID, deep-link схемы, названия коллекций и `/api/events`-контракты.
- Не создавать бинарные ассеты.
- Не выдумывать факты: если чего-то нет в коде — писать «нет в коде» / «уточнить у владельца».
- Документ — на русском языке.
- Коммит **не делай** — просто запиши файл на диск. Коммит выполнит вызывающая сторона.
- Не изменяй и не удаляй другие файлы; в рабочей копии есть чужие незакоммиченные изменения (не трогать, не откатывать).
