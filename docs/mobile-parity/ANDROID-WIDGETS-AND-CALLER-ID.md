# Android: виджет и карточка звонящего

Добавлено по запросу владельца 04.10.2026. Это отдельное нативное расширение после текущего паритета, а не готовая функция. Источники статусов: M1-T8/M1-T9 в `docs/ROADMAP.md`. Заход T (AJ) продолжает тему; новые функции не входят в его область.

## 1. Виджет рабочего стола (M1-T9)

- Ближайшее мероприятие/заказ и следующий контакт, просроченные задачи; переход в соответствующие карточки и действие создания заявки.
- Данные из последней локальной копии текущего аккаунта; подпись времени обновления и состояния отсутствующих/непрочитанных данных. Фоновые обновления ограничены Android, постоянную свежесть не обещать.
- При выходе, смене аккаунта и отзыве доступа очищать проекцию и активные виджеты; не переносить данные между tenant. На заблокированном устройстве учитывать выбранную политику приватности.
- Нативный Android-модуль и воспроизводимый Expo config plugin; новая development/preview-сборка. Expo Go для проверки недостаточен. Package ID и схемы переходов сохраняются.

## 2. Определитель входящих и исходящих звонков (M1-T8)

Первый кандидат — `CallScreeningService` и системная роль `ROLE_CALL_SCREENING` на Android 10+. Получение роли добровольное; объяснять замену другого определителя. Обычную звонилку не заменять, вызовы не блокировать.

- Получать номер и направление обычного телефонного вызова, включая запуск при закрытом интерфейсе. Работа после принудительной остановки приложения не гарантируется.
- Номера из телефонной книги и требование `READ_CONTACTS` проверить отдельно. Скрытые/недоступные номера не восстанавливать и не угадывать.
- Звонки мессенджеров, запись звука, длительность/факт ответа и чтение общей истории не входят в первый объём: получение номера не даёт этих возможностей.
- Не добавлять `READ_CALL_LOG`/SMS-разрешения по умолчанию. Перед публикацией проверить актуальные правила Google Play и Data Safety.
- После разговора предложить результат/заметку и следующий контакт. Не создавать серверную запись автоматически без согласованного контракта и защиты повторов.

## 3. Всплывающая карточка входящего звонка

Основное требование владельца: во время входящего звонка показать, найден ли клиент, его ФИО/данные и ближайшее связанное мероприятие с кратким описанием.

- Компактное окно поверх экрана вызова, не перекрывающее ответ/отбой; закрытие и перемещение. Переходы «Открыть клиента» и «Открыть мероприятие/заказ» через существующие маршруты, с проверкой авторизации.
- Нормализованный номер сопоставлять с локальными контактами текущего tenant, включая допустимые дополнительные номера. Несколько совпадений обозначать явно, без молчаливого выбора.
- Ближайшая предстоящая связанная работа: дата/время, заголовок/тип и короткое описание; canceled/closed исключить, draft явно обозначить. Неизвестную дату не выдавать за ближайшую; правила текущего/уже начавшегося мероприятия уточнить по коду при брифе.
- Различать «Клиент не найден в последней копии», «Данные пока недоступны», «Номер скрыт», «Несколько клиентов», «Нет предстоящих мероприятий». Ошибка базы или отсутствие синхронизации не доказывают отсутствие клиента.
- Сначала своевременно разрешать входящий вызов штатным ответом Android, затем искать/показывать контекст; не ждать сети внутри системного срока ответа.
- Для наложения проверить необходимость специального разрешения `SYSTEM_ALERT_WINDOW` и ограничения целевой версии Android/прошивки. При отказе — обычное уведомление, если оно разрешено; отсутствие обоих разрешений объяснять в приложении. Не использовать AccessibilityService как обход ограничений.
- По умолчанию ФИО и описание не раскрывать на заблокированном экране. Отдельное явное согласие на показ персональных данных; проверить отсутствие утечки через уведомления, экран недавних приложений и журнал.
- Не сохранять открытый текст телефонов/ФИО в общих настройках ради удобства нативного чтения. До реализации спроектировать безопасный доступ нативного сервиса к SQLCipher/минимальной зашифрованной проекции и ключам без зависимости от запущенного JS. В текущем треке паритета storage/sync не менять.

## 4. Порядок работ и приёмка

1. Завершить T (AJ) и существующую приёмку U (AK) либо честно зафиксировать её внешние блокеры.
2. Отдельный бриф нативного прототипа: разрешения/роль, получение входящего и исходящего номера, карточка при закрытом интерфейсе, отказ роли и разрешений. До теста на реальном телефоне не объявлять техническую приёмку завершённой.
3. Отдельный заход интеграции с зашифрованной локальной базой и безопасностью tenant/выхода; тесты нормализации, неоднозначности и выбора работы.
4. Отдельный заход виджета рабочего стола и его обновления/очистки.
5. Одна согласованная Android-сборка и телефон: известный/неизвестный/скрытый номер, контакт телефонной книги, несколько совпадений, offline, закрытое приложение, блокировка экрана, отказ уведомлений/наложения, выход/смена аккаунта, отменённая/закрытая/черновая работа. Дополнительные прошивки — отдельная приёмка.
