## Реализовано и сверено с текущей PWA

- Список: заголовок «Клиенты» со счётчиком, compact-поиск и добавление; «Все клиенты / Фильтры», overlay 260 dp; группы all/requests/events/canceled. Выбранная группа меняет подпись первой кнопки; её нажатие возвращает all.
- Статистика по основному clientId, request/active/finished/closed/canceled с dateEnd; последняя заявка по requestCreatedAt ?? createdAt ?? eventDate. Сортировка точно как текущий ClientsContent: дата последней заявки, при отсутствии дат — число заявок. Группа events включает только текущие, а не закрытые/завершённые.
- Карточка: без аватара, одно строковое ФИО, muted-иконка, разделители; последняя заявка с web-статусом, предпочтение или комментарий; только положительные счётчики и общие QuickContacts. Меню отдельно от основного тапа, предусмотрены свайпы. Pending/syncing/failed/conflict различаются.
- Просмотр: web-порядок шапка/контакты/приоритет и комментарий → работы → финансы → документы → реквизиты → значимые даты. Телефон копируется, комментарии не показывают HTML. KPI считают основные работы/прямые транзакции; дополнительные контакты и связанные транзакции доступны в раскрытии с явной подписью. Факт не включает обязательства. История, переписки и создание с clientId сохранены.
- Форма: единое ФИО и порядок контактов из web, CompactField, реквизиты свёрнуты. Если ФИО меняют, оно хранится в firstName, остальные части очищаются как в web; если меняют другое поле, исходные части имени сохраняются. Email/Viber/город доступны в дополнительных данных. Реквизиты/messengerPushMuted/даты/подтверждения мессенджеров не сбрасываются при несвязанной правке.
- Ошибка загрузки/отсутствующая запись не превращаются в пустую форму; есть повтор. Ошибка сохранения не уничтожает черновик, повторный тап заблокирован, выход с изменениями подтверждается. H-handoff создания клиента сохранён.
- Merge: прямой route защищён при offline и local/pending/failed/conflict; только синхронизированные кандидаты. Preview сверяет пару ID; изменение дубля сбрасывает preview. Перед POST повторно читается сеть, подтверждение не отправляет второй запрос. После POST результат читается через существующий GET клиента, затем обновляется cache и штатный sync. Это также не теряет confirmed-contact поля, обрезанные старым merge DTO. 403 не объявляется успехом.
- Документы: palette, loading/error/not-found/retry, объяснение local-ID ограничения; прежние файловые экспорты/picker/share/очередь не переписаны. Ошибка signed URL отображается, повторные файловые действия блокируются.

- Четыре API-статуса/dateEnd/невалидная дата, отсутствие чужих связей, поиск имени/номеров/мессенджеров/local ID, сортировка, plain-comment.
- Empty/create против no-matches/reset, error/retry/loading, overlay поверх смонтированного списка и Back, длинное имя, light/dark palette, pending/failed/conflict и удаление через outbox один раз.
- Просмотр/копирование/связи/реквизиты/история/создание, отдельные обязательства; загрузка/ошибка не выдаются за отсутствие клиента.
- Форма: свёрнутые реквизиты и сохранность полей, отсутствующая запись, повтор чтения, ошибка/повторный тап save, подтверждение выхода, H-return.
- Merge: offline/unsynced/local guard, смена кандидата, preview/confirm/readback, один POST, потеря сети, 403 и чужая пара.
- Документы: local ID, missing/error/retry и signed-URL 403 (имитация ответа API, не реальная staging-проверка tenant).

## Ограничения и отличия, не выдаваемые за паритет

- Нет устройства: 320/360/390, font scale, действительный размер контактов, свайпы, клавиатура, аппаратный Back/TalkBack, picker/share, restart и offline→online не проверены. Компонентные light/dark проверки не заменяют скриншоты APK.
- Server/staging с двумя tenants, тарифные запреты файлов и native SQLCipher не запускались. Подмена 403 в тесте не доказывает серверную изоляцию.
- Отзывы клиента есть в текущем web, но bearer API нет (AL). Fake reviews UI и web-session запросы не добавлялись.
- PWA phone-check/выбор существующего клиента, вставка и нормализация clipboard-контактов ещё не перенесены; отдельного проверенного native duplicate-check сценария нет. Не добавлена фиктивная «Проверить».
- Уведомления мессенджера сохраняются, но их редактор требует доступных сведений об активных интеграциях; без подтверждённого источника не рисуется постоянный переключатель.
- Просмотр открывает списки связей раскрытием в том же экране, а не отдельной web-модалкой. Обязательства сознательно отделены от факта (web client-view считает все суммы; требование native-плана — не включать обязательства).
- Фон Surface — существующее native-приближение градиента, системный шрифт и elevation не pixel-perfect. Полный редизайн документов — X.
