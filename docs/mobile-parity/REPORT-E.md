# Задание E — экран «Важное», этапы I и J

Дата: 01.10.2026. Реализация подготовлена в рабочей копии, без коммита. Основание — `BRIEF-E.md` и §5.5–5.6, §6.1–6.2 `MOBILE_PWA_PARITY.md`. Прочитаны `AI_HANDOFF.md`, Mobile Track в `ROADMAP.md`, фактические PWA-селекторы и offline-мутации Android.

**Что реализовано**

- `mobile/src/features/attention/selectors.ts`: чистые проекции `additionalEvents[]`, ожидаемых/просроченных задатков, незакрытых прошедших работ, ближайших работ и ежегодных значимых дат клиентов. `now` передаётся аргументом. Поля доменных сущностей и persisted-статусы не добавлялись.
- `AttentionScreen.tsx`: «Важное» вместо старой главной. Порядок: ненулевые summary-счётчики → условное закрытие → просрочено/сегодня/завтра → работы на три дня → даты клиентов → native sync при очереди или незавершённой попытке. Первая заявка предлагается перед обзором, если работ ещё нет. Финансы месяца удалены из этого экрана.
- Summary измеряет координаты секций и прокручивает текущий экран. Нулевые счётчики не показываются, пустые секции задач имеют самостоятельные тексты. Сообщения и фиктивный счётчик «0» не добавлены.
- Работы показаны существующим `MobileEventCard`, с клиентом, услугами и транзакциями. Значимая дата содержит название, клиента, комментарий, дату, оставшиеся дни и переход в карточку клиента.
- `TaskCard.tsx`: заголовок, срок, описание, контекст работы и адрес; выполнение/отмена, редактор названия/комментария/срока, удаление с подтверждением и перенос. Некорректный срок и пустое название не сохраняются; редактор можно отменить. У задатка есть переход к работе, без подмены оплаты флажком выполнения.
- `actions.ts` и расширение `shared/domain/taskActions.ts`: все изменения задач идут через `getCachedEntity` → доменное преобразование → `saveLocalEntity` → существующий outbox. В payload только `additionalEvents`. Прямых API-запросов и remote fallback нет. Команды одной работы сериализованы; свежий cache сохраняет изменения соседних задач. Поддержаны задачи без `_id`; при сдвинувшемся/изменённом массиве действие безопасно отклоняется. Контракт push `TaskAction` оставлен прежним.
- `index.tsx` и `tasks.tsx` экспортируют одну реализацию. Старый route задач сохранён.
- Небольшое расширение `EventsScope.tsx` и `events.tsx` необходимо для работающего перехода к прошедшим **с фильтром незакрытых**. Он не меняет статусы работ и не закрывает их массово. Фильтр сбрасывается кнопкой, выбором другого фильтра и обычным входом из меню. Основной редизайн списка работ остаётся этапом L.
- Три разных состояния: пустой cache → создание заявки; пустой фильтр незакрытых → сброс; ошибка чтения → Notice и повтор. Загрузка не изображает пустой успешный результат. Ошибка любой коллекции обзора не даёт показать недостоверный расчёт задатков или счётчиков.
- `useSyncRunState` сохранён. Сводка использует существующие `getSyncQueueCounts` (включая файловую очередь), `getOutboxSummary`, штатный `runSync` и переход `/sync` для подробностей, индивидуального retry и конфликтов. Чтение очереди имеет отдельный error/retry. Web-очередь не копируется.

**Закреплённая семантика**

1. Срок задачи строго раньше `now` — просрочен, в том числе в течение сегодняшнего дня. Ровно `now` — ещё «Сегодня». Полночь завтра относится к «Завтра», полночь послезавтра — уже вне двух дневных секций. Невыполненная задача без срока не становится просроченной.
2. Выполненные следуют после невыполненных и не увеличивают pending-count. Срок в сегменте «Сегодня»/«Завтра» сохраняет выполненную задачу в этом сегменте независимо от `doneAt`. Просроченная выполненная задача видна только при `doneAt` сегодня и остаётся в «Просрочено». Выполненная без срока/с некорректным сроком/с поздним сроком показывается в «Сегодня» только при `doneAt` сегодня. Переход суток убирает старые выполненные просроченные задачи.
3. Отсутствие даты самой работы не скрывает её датированные задачи. Время экрана обновляется раз в минуту, при фокусе и возвращении приложения на передний план. Используется календарная зона устройства, как у существующих native-контролов дат.
4. Ожидаемые задатки: `active`, `waitDeposit`, без положительной связанной транзакции `income` категории `deposit`/`advance`. Следуя фактическому PWA-селектору, любой положительный такой платёж снимает ожидание; это не расчёт остатка до `depositExpectedAmount`. Доход иной категории, расход и нулевая сумма задатком не считаются. Ожидания без срока и с будущим сроком есть в проекции; в «Просрочено» добавляются только задатки с валидным сроком `<= now`.
5. Незакрытые прошедшие: `active`, не передано коллеге, `dateEnd ?? eventDate < now`; работа без даты не считается прошедшей, продолжающаяся многодневная не предлагается к закрытию. `canceled`/`closed` не дают активных задач, задатков и ближайших работ.
6. Переносы сегментные: «Просрочено»/«Сегодня» → завтра или послезавтра; «Завтра» → послезавтра либо +2 дня относительно завтра. День вычисляется от текущего календарного дня, время задачи сохраняется. Выполненную задачу можно вернуть через undo; новые persisted-статусы не вводятся.
7. Даты клиентов повторяются ежегодно и сортируются по ближайшему наступлению, включая переход декабря в январь.

**Native-адаптации**

- Во всех длинных секциях первые 12 записей дополнены кнопкой «Показать все (N)». Она раскрывает весь набор внутри текущей прокрутки; summary считает все невыполненные задачи, а не только первые 12. Это применяется и к работам/датам клиентов.
- Native читает полный локальный cache. Задачи открытых прошедших работ сохраняются в обзоре, а продолжающаяся многодневная работа входит в трёхдневный интервал по пересечению дат. Это явно шире PWA-overview, который получает `scope=upcoming` и выбирает ближайшие по дате начала. Цель — не потерять задачи и текущую многодневную работу в offline-обзоре. `closed` и `canceled` исключены явно.
- Редактор задачи расположен в карточке; срок вводится через существующий валидатор формата `ГГГГ-ММ-ДД ЧЧ:ММ`, без новых native-зависимостей. Состояния и новые карточки используют существующие токены light/dark.
