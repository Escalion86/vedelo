## V — услуги

- Группы идут по `order`, услуги внутри — по русскому названию; группы раскрыты по умолчанию. «Без группы» включает ссылки на удалённые группы. При отсутствии групп список плоский. Архив скрыт по прежнему mobile-правилу, но учитывается при переносе из удаляемой группы.
- Карточка показывает название, длительность, цену, описание до трёх строк, существующее изображение и состояние очереди. Длинные названия и суммы допускают перенос; цвета из текущей palette, без локальных hex.
- Ошибка чтения любой коллекции показана как ошибка прайса с повтором, а не пустой успешный список. Загрузка и реальное отсутствие услуг разделены.
- Формы ждут полного чтения услуги/группы и связанных данных. Отсутствующая запись и ошибка чтения не превращаются в пустую форму. Есть повтор загрузки, сохранение ввода после ошибки, блокировка повторных save/delete и ввода при операции, подтверждения удаления и выхода с правками.
- При существующей записи отправляются только изменённые поля; нетронутые description, duration, price, groupId, images, archive и прочие поля сохраняются существующей мутацией. Ошибка чтения групп блокирует форму, а недоступная исходная группа не заменяется автоматически на null.
- Создание принимает выбранный local groupId. Перед записью проверяется существование сохранённой записи и вновь выбранной группы; удалённая запись не воскрешается пустым create.
- Удаление группы: повторное чтение услуг, снятие `groupId` через `saveLocalEntity`, затем `deleteLocalEntity` группы. Каждая услуга перечитывается перед patch, чтобы не воссоздать параллельно удалённую запись. При частичной ошибке группа не удаляется; уже перенесённые услуги остаются, сообщение объясняет частичный результат и повтор доступен. Атомарность не обещается, outbox/sync не менялись. Действия обозначены как локальные изменения в очереди, а не подтверждённый серверный результат.

## W — списки и настройки

- Города/default/типы записываются существующим bearer PUT `/mobile/v1/lists`; терминология — только PUT `/mobile/v1/settings/terminology`. Подписи и пояснения используют resolver.
- Чтение сервера и последняя офлайн-копия различаются. До получения данных нет ложного пустого списка; есть ошибка/повтор. Поздний GET, поздний кэш и повтор чтения не стирают изменённый draft, включая ещё не добавленные строки.
- Пробелы/пустые значения и дубликаты без учёта регистра обработаны; применяются существующие серверные лимиты 100 элементов и 100 символов. Первый город становится default, удаление default снимает его. Удаление подтверждается и вступает в силу после сохранения списков. Незавершённая строка требует добавления перед save и не исчезает молча.
- Save блокирует повтор и изменение полей. PUT проверяется по `success === true`, ID и значениям; затем выполняется GET того же точного endpoint с повторной проверкой success, того же ID и значений. Ошибка/несовпадение не дают сообщения успеха и не стирают ввод.
- Кэш обновляется объединением, поскольку `upsertEntities` заменяет весь payload. Узкий DTO списков меняет только свои поля, сохраняя терминологию и прочие settings/custom. Для пустого кэша полный ответ служит исходным снимком, включая специализацию авторежима. UI-записи списков/терминологии упорядочены; Query-кэш обновляется также объединением. Ошибка локальной записи после подтверждённого GET обозначается отдельно.
- Выход с черновиком требует подтверждения. Обе palette и selected/disabled/busy-состояния проверены компонентными тестами. Выбор light/dark не включён: остаётся этап AJ.

## Остатки и непроверенное

- Узкий terminology PUT принимает только `primaryEntityTerminology`. Общих bearer API для независимого изменения часового пояса, стандартной длительности, передачи коллеге и `eventFormVariant` не найдено. Onboarding POST умеет менять timezone/transfer, но требует профиль и одновременно меняет состояние мастера/специализацию/другие параметры; он не использован как общий settings-save. `eventFormVariant` и стандартная длительность отсутствуют в текущем mobile serializer. Эти функции остаются контрактными пробелами, не добавлены фиктивные переключатели.
- Native-адаптации: формы открываются stack-экранами, списки редактируются прямо в разделе вместо web-модалок, длительность вводится в минутах. Отдельный web-просмотр/клонирование услуги и изменение/загрузка её изображения не переносились; существующее изображение отображается и сохраняется при правке. Pixel-perfect, браузерная фактура и системный шрифт не подтверждены.
- В PATH нет adb/Java и подключённого телефона. Реальные 320/390 dp, увеличенный шрифт, клавиатура, TalkBack, native Back/жесты, офлайн-удаление группы с перезапуском и последующим серверным sync не проверены. Jest использует fixtures и mocks локальных операций; он не проверяет SQLCipher/outbox на устройстве и не доказывает атомарность.
- Staging/bearer-прогон двух tenant и реальные API-ошибки/доступы в этом заходе не выполнялись. Серверные tenant-фильтры прочитаны и не изменены; новые разрешения/эндпоинты не вводились.
- Корневой ESLint игнорирует mobile/**. Next.js build и Android/EAS build не запускались: web-код не менялся, native-инструментов здесь нет. Компонентные проверки не выдаются за device-приёмку.
