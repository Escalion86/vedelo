# Задание C — дизайн-токены, тема и базовые UI-примитивы (этапы D и E плана)

Репозиторий: `~/projects/ArtistCRM`, ветка `codex`. Прочитай `AGENTS.md`, затем `docs/MOBILE_PWA_PARITY.md` — §4.1, §4.2, §4.3 (дизайн-контракт), §5 (анатомия компонентов), §6.1 (границы захода), §6.2 этапы **D** и **E**.

## Цель захода

Привести дизайн-систему Android-приложения к контракту мобильной PWA, чтобы последующие экранные этапы строились на ней.
Реализуй ровно этапы **D** (токены + тема) и **E** (базовые примитивы). Экраны массово **не** переписывать.

## D — токены и тема

Файлы: `mobile/src/shared/ui/theme.ts`, новые `mobile/src/shared/ui/ThemeProvider.tsx` (имя уточни), при необходимости `mobile/src/shared/providers/AppProviders.tsx`, новый небольшой тест токенов.

- Перенести пары светлых/тёмных токенов из §4.2 без выдумывания значений: canvas/surface/toolbar, `--ui-primary` и производные (`onPrimary`, secondary-набор, pressed-наборы), card-title/card-meta/card-muted, `navigationBackground/Text/Active`, `fabBackground/Foreground`, транзакционные `income/expense` с pressed/outline, временные chips (`status.overdue/today/tomorrow/upcoming/neutral`), статусы работы из §4.2, Notice-роли (§4.2, абзац про сущности без взаимно однозначного соответствия).
- Тема — через provider и **фабрики стилей от palette**. Мутация экспортированного `colors` не обновит уже выполненный `StyleSheet.create`; статический singleton-импорт сохрани как временный light-bridge, чтобы существующие экраны не сломались.
- Preference темы хранить **вне** SQLCipher (не менять схему БД, outbox, ключи кэша). Публичный переключатель темы пока **не включать**: он включается на этапе AJ плана, после миграции всех пользовательских экранов.
- Только светлая палитра сейчас в проде; тёмная должна быть доступна в provider и покрыта тестом, но не включаться глобально.

## E — базовые примитивы

Файл: `mobile/src/shared/ui/components.tsx` плюс новые `Notice.tsx`, `FilterOverlay.tsx`, `CompactField.tsx` (имена можно уточнить, границы ответственности сохранить) и focused-тесты.

- `PageHeader`: заголовок `clamp(24px,4vw,32px)`/weight 650/line-height 1.05/tracking −.035em, опциональный счётчик 16/500, subtitle — необязательный (см. §4.3).
- `Surface`: варианты (card/toolbar/KPI), рамка 1 px, радиусы по §4.3 (для карточек списка — НЕ общий radius 18), elevation по §4.2 (elevation ≠ CSS-тень: без «точных» числовых обещаний).
- `Notice`: семантические роли (success/warning/danger/info) с точными цветами PWA-блоков (§4.2), иконка + текст, доступность.
- `StatusChip`/временные chip-стили: значения из таблицы §4.2 («Просрочено/Сегодня/Завтра/Ближайшее/Нейтральный»), цвет не единственный носитель смысла.
- `EmptyState`: опциональные icon (48) и CTA-действие, отступы 16×24, gap 8.
- `CompactField`/поиск: label 12/600, gap 4, border 2, min-height 40, radius 4, paddingX 8; **не уменьшать** вслепую существующие многострочные формы (`Field` 48/radius12 остаётся для форм).
- `FilterOverlay`: слой поверх списка, строки min-height 48/font 15.2, ширина `min(340|260, viewport−24)` по §4.3, открытие не сдвигает координату первой карточки, Back закрывает overlay.
- Кнопки: `pressed` вместо web-hover, отдельные pressed-токены primary/secondary, disabled opacity .65, loading блокирует повторное действие и не стирает введённый текст; `accessibilityState` (selected/expanded/disabled/busy) и `hitSlop` для зоны касания.

## Жёсткие границы

- Меняются только файлы внутри `mobile/`. Web-код (`app/`, `server/`, `layouts/`, `helpers/`, `components/`, `models/`, `schemas/`) не трогать.
- **Не редактировать** `mobile/src/shared/storage/**`, `mobile/src/shared/sync/**`, схему SQLCipher, outbox, ключи кэша, `operationId`, tombstones, файловые очереди. Тема не должна зависеть от БД.
- Не менять package ID, схемы deep link, `app.json`, `eas.json`, EAS-профили.
- Не создавать бинарные ассеты и не подключать сторонние шрифты (нет бинарных файлов без явного запроса; если Inter Tight недоступен без бинарника — оставить системный fallback и записать это как явное ограничение точности).
- Не менять серверный код и мобильный API-контракт.
- `mobile/src/shared/notifications/index.ts` (неотслеживаемый, чужая параллельная работа) **не трогать**.
- В рабочей копии есть чужие незакоммиченные изменения — не откатывать, не удалять, не коммитить.
- Не делать массовых regex-замен цветов по всему `mobile/`. Миграция экранов — отдельные этапы.
