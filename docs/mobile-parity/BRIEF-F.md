## L — список работ и фильтры

Файлы: `mobile/app/(tabs)/events.tsx`, новые `mobile/src/features/events/filters.ts`, `EventFilters.tsx`, `filters.test.ts`; `EventCalendar.tsx` — только presentation.

- Отдельный чистый selector с тестами: scope `Предстоящие/Прошедшие` задаётся **навигацией** (через `EventsScope`), а не только чипами; внутри scope — фильтры PWA: город, проверенность импорта, статусы, «передано коллеге», а для прошедших — быстрые пресеты (в т.ч. «не закрыто», уже поддержано через `isPastUnclosed`).
- Текущие чипы `requests/upcoming/past/all` не эквивалентны PWA-фильтрам. Границы: заявка без даты, многодневная работа (`eventDate`/`dateEnd`), `canceled`/`closed`/`isTransferred`, границы суток — всё покрыть тестами selector.
- Фильтры — overlay поверх списка (`FilterOverlay`): открытие **не сдвигает** координату первой карточки, закрытие по Back/тапу вне, выбранное состояние видно, фокус возвращается. Не добавляй строку поиска работ: в PWA её нет.
- Смена режима список/календарь и выбор дня не должны терять применённые фильтры и позицию списка.
- Заголовок: `PageHeader` с count/subtitle по §5.4 (subtitle не обязателен на каждом экране).
- Пустые состояния и ошибки по §5.5 — три разных состояния: нет данных (создание), фильтр ничего не нашёл (сброс фильтра), ошибка чтения (повтор). Отдельно: для «прошедших» создание не навязывается.
- Модальные сегменты из старого макета (`docs/mockups/events-segment-switch.html`) **не** подключать: это отдельное решение владельца, а не текущий runtime.

## M — карточка работы

Файлы: `mobile/src/features/events/MobileEventCard.tsx`, `eventCard.ts` и существующие тесты; новый `mobile/src/shared/ui/QuickContacts.tsx`.

Анатомия строго по §5.1 и `design-qa.md`:

1. Внешняя интерактивная поверхность, слева узкий маркер статуса, overlay загрузки/ошибки; отдельный overflow-trigger 40×40 сверху справа (тап по нему не открывает карточку).
2. Полноширинная верхняя строка: условные иконки (передача / договор / непроверенный импорт / ошибка календаря / отсутствующий клиент) → название типа и услуг. Один договорный значок, **без** отдельной строки «По договору». Ниже — непрерывный разделитель, справа место под trigger.
3. Средний ряд: **дата** (колонка 58: день недели, день, месяц, время + вертикальная граница) → **адрес и внимание** (адрес, переход в 2ГИС; предупреждение задатка или ближайшая задача с датой и названием; `+N` остальных) → **сумма** (обязательство, источник API, «оплачено/договор» либо итог закрытой работы).
4. Нижняя строка с верхним разделителем: имя клиента → быстрые контакты → `+N` дополнительных контактов с именами/комментариями. Footer прижат к низу схемой `auto / 1fr / auto`, вертикальная граница даты касается обеих горизонтальных.

Дополнительно:

- Геометрия: внешние отступы карточки 8×4, shell radius 8, колонки 58 / 1fr / auto, gap 12; высота виртуализированной строки должна совпадать с фактическим shell, footer не обрезается. Общий `Surface` radius 18 здесь не подходит.
- **Семантика статусов важна:** native сейчас считает `canceled` финальным и показывает итог — в PWA итог показывается только для `closed`. Исправь и закрепи тестом.
- Финансовые расчёты (обязательства, legacy-категории, оплаты, возвраты) не меняй молча: если расхождение обнаружено — сверь на фикстурах и опиши в отчёте.
- `+N` контактов — раскрываемый список, а не просто визуальная метка.
- Тап контакта не должен одновременно открывать карточку.
- Проверить случаи: длинное название, ноль/одно/много контактных действий, отсутствующий клиент, локальный (не синхронизированный) ID, `draft`/`active`/`canceled`/`closed`.
