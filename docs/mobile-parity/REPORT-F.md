# Отчёт F — список и карточка работ, этапы L и M

Дата: 01.10.2026. Реализация на диске, без коммита. Код этапов L/M готов; визуальная приёмка на Android остаётся непроверенной.

## Реализовано

### L: список

- Убраны четыре старых scope-чипа. Предстоящие/прошедшие выбираются существующей навигацией через `EventsScope`; переход из «Важного» включает «Не закрыто». Поиск и макетные верхние сегменты не добавлены.
- `filters.ts` — чистый selector, defaults и past presets. `EventFilters.tsx` использует готовый `FilterOverlay`: город, проверенность, статусы, передача; для прошедших — «Не закрыто», «Только закрытые», «Только отменённые». Выбранное состояние видно на trigger и строках; невозможно выключить последний статус.
- Панель фильтров находится в Modal, а не в потоке списка. Back, тап вне, возврат фокуса наследуются от готового `FilterOverlay`. Его реализация не изменена.
- Два экземпляра FlatList сохраняют своё состояние: переключение списка/календаря меняет видимость и доступность касаний/TalkBack без размонтирования списка. Выбор дня/месяца не меняет фильтры. Невидимый список сохраняет размеры, чтобы не сбрасывать scroll offset. Это проверено на уровне жизненного цикла компонента; точная позиция прокрутки на Android ещё требует device QA.
- `PageHeader` показывает терминологию, количество отфильтрованных работ и scope. Toolbar содержит фильтры и одну кнопку смены режима.
- Разделены загрузка, ошибка чтения с повтором, отсутствие данных с созданием, отсутствие совпадений со сбросом и пустой день календаря с переходом к списку. Для прошедших создание не предлагается. Ошибки связанных справочников/оплат показываются отдельно с повтором чтения.
- Даты повторно оцениваются при фокусе и каждые 30 секунд на открытом экране. `EventCalendar` изменён только в presentation: палитра light/dark и accessibility selected.

### M: карточка

- Внешние отступы 8×4, shell radius 8, минимальная высота 184; заголовок / растягиваемый средний ряд / footer. Виртуализация измеряет фактическую строку, фиксированный `getItemLayout` не вводится; увеличенный шрифт может увеличить высоту.
- Дата занимает 58 dp, средняя колонка растягивается, сумма имеет естественную ширину с ограничением; gap 12. Вертикальная граница даты примыкает к обоим разделителям. Заголовок однострочный, справа зарезервирован trigger 40×40.
- Слева маркер статуса; в заголовке индикаторы передачи, единственного договора, непроверенного импорта, ошибки календаря и отсутствующего клиента. В средней строке — адрес/2ГИС через существующий `buildEventNavigationLinks`, предупреждение задатка либо датированная задача и `+N`, обязательство, источник API и суммы.
- «Итог» теперь выводится **только для `closed`**. `draft`, `active` и `canceled` показывают «Оплачено / договор». Финансовые формулы сохранены, см. сравнение ниже.
- Новый `QuickContacts`: телефон, WhatsApp, Telegram, VK, email, Viber, Instagram при наличии соответствующих данных. На узкой карточке часть действий убирается в раскрываемый список. `+N` дополнительных контактов открывает имена, комментарии, действия связи и переход к клиенту; недоступная запись обозначается явно.
- Контакт, 2ГИС, overflow и sync-overlay останавливают распространение нажатия. Меню предлагает существующие переходы: просмотр, редактор незакрытой работы, документы, добавление финансов для active, клиент, синхронизация при необходимости. Новых API-операций нет.
- Сохранены локальные ID, pending/syncing/failed/conflict; есть loading/error overlay. Закрытые контактные панели не монтируют Modal и не подписываются на safe-area.
- В `AttentionScreen` добавлена только передача уже загруженного `clientsById` в переиспользуемую карточку, чтобы дополнительные контакты раскрывались и на «Важном». Логика обзора не переписана.

## Семантика, закреплённая тестами

Граница scope — валидный `dateEnd ?? eventDate`: окончание `< now` означает прошедшее, равное `now` ещё предстоящее. Округления до суток нет: утренняя завершённая работа сегодня уже относится к прошедшим. Без даты/с некорректной датой — предстоящие. Статус сам по себе не переносит запись между scopes. Многодневная работа остаётся предстоящей до окончания.

Defaults повторяют PWA: предстоящие — заявки и подтверждённые; прошедшие — завершённые и закрытые; отменённые по умолчанию скрыты. Полный набор доступных статусов отключает status-фильтрацию, как в PWA, включая старые заявки в прошедшем scope. Передача — независимый фильтр `all/only/exclude`.

«Не закрыто» использует существующий `isPastUnclosed`: только active с прошедшим окончанием, без передачи; исключает draft/canceled/closed и продолжающиеся многодневные работы. Переход из «Важного» сбрасывает прежние город/проверенность, чтобы показать весь счётчик незакрытых. Обычный вход из меню снимает этот навигационный preset; ручные фильтры scopes остаются отдельными.

Проверенность повторяет `helpers/fileImport.mjs`: для `importedFromFile` используется строго `fileImportChecked === true`; иначе `Boolean(calendarImportChecked)`. Отсутствующее поле не считается проверенным. Город сравнивается после trim; список городов строится внутри scope.

Сортировка предстоящих: API-заявки без даты, датированные по возрастанию, остальные без даты; при равенстве — `requestCreatedAt` по убыванию. Прошедшие — по `eventDate` по убыванию. Источник API и признаки импорта читаются как необязательная presentation-проекция существующего sync payload. Общие persisted types и cache schema не менялись.

Тесты покрывают границы с фиксированным временем/смещением UTC+7, полночь и равные моменты в разных ISO-offset, отсутствие/некорректность дат, многодневность, все четыре статуса, передачу, импорт, пересечение фильтров, presets и сортировку. Компонентные тесты проверяют theme tokens, длинный заголовок, один договорный значок, 0/1/5 контактных действий, отсутствующего клиента, локальные ID, отдельные нажатия, раскрытие контактов, синхронизацию, overlay, навигацию, сохранение экземпляра списка и три типа пустоты/ошибок.

## Финансы: найденное расхождение с PWA

Сверены `layouts/cards/EventCard.js`, `helpers/eventCloseSuggestion.js`, `helpers/additionalEvents.js` и текущий native `eventCard.ts`. Код web не менялся.

Фикстура: legacy advance 1 000, final_payment 3 000; refund 500 и travel 200; обязательства income 2 000 и expense 700; договор 6 000.

| Показатель | Native, сохранённая формула | PWA EventCard, текущая формула |
|---|---:|---:|
| Оплачено | 4 000 | 6 000 |
| Расходы | 700 | 1 400 |
| Итог | 3 300 | 4 600 |

Причина: native исключает `paymentMethod=obligation` из факта, PWA-карточка суммирует все income/expense. В F это **не выравнивалось**. Добавлен только индикатор наличия обязательств. Legacy `advance` учитывается как задаток, `client_payment`/`final_payment` — как доход, refund — как расход; возврат не вычитается повторно из «Оплачено». Без обязательств эти суммы совпадают. Фикстуры закреплены в `eventCard.test.ts`.

Есть связанное расхождение предупреждения о задатке: PWA `hasDepositByTransactions` считает положительный deposit/advance даже с методом obligation; native проверяет фактический задаток и такое обязательство не снимает предупреждение. Это поведение также сохранено и покрыто тестом. Частичный положительный фактический задаток по прежней логике снимает именно предупреждение о полном отсутствии задатка; формула `depositPending` при этом не изменена.
