# Очистка legacy-категорий транзакций

Версия 1.27.27. Скрипт `scripts/migrateTransactionCategories.mjs` заменяет:

| Было | Стало |
| --- | --- |
| `client_payment` | `final_payment` |
| `advance` | `deposit` |
| `colleague_percent` | `referral_in` |

## Запуск

Сначала развернуть совместимый код приложения и сделать резервную копию БД.
Задать `MONGODB_URI` и `MONGODB_DBNAME` в `.env.local` или окружении процесса.
С версии 1.27.32 скрипт использует загрузчик `@next/env` самого Next.js:
загружает env-файлы из корня проекта и раскрывает `$VARIABLE` / `${VARIABLE}`.
Уже заданные переменные окружения имеют приоритет. При `NODE_ENV=production`
используется production-порядок файлов, иначе development-порядок Next.js.
Строки подключения и данные клиентов не выводятся. Не добавлять `--env-file`
при прямом запуске через `node`: он заранее загрузит значения без подстановки.

```sh
# Только отчёт, никаких изменений
npm run transactions:migrate-categories

# Ограничение одной организацией
npm run transactions:migrate-categories -- --tenant=0123456789abcdef01234567

# Применение ко всем организациям
npm run transactions:migrate-categories -- --apply
```

Без `--tenant` обрабатываются все организации, каждый update включает tenant
прочитанной записи. Преобразование меняет только `category`, `updatedAt` и
`syncVersion` (для получения изменений Android-клиентами). Сумма, тип доход/расход,
дата операции, способ оплаты, комментарий и связи не меняются. Старые записи без
версии получают версию 2. История действий не переписывается.

Повторный запуск безопасен: актуальные категории не выбираются. При параллельном
изменении исходной категории, версии или `updatedAt` запись пропускается как
конфликт. После завершения повторить предварительный отчёт.

Отчёт содержит только счётчики:

- `found`, `eligible`, `updated`, `categories` — найдено, доступно для изменения,
  изменено и распределение исходных категорий;
- `conflicts` — изменённые параллельно записи; повторить запуск;
- `invalidTenant`, `invalidVersion` — записи, требующие отдельного разбора;
- `nonIncome` — нетипичные записи, у которых тип не `income`; категория
  нормализуется, направление денег сохраняется.

Код выхода 0 — завершено; 2 — есть пропуски/конфликты; 1 — ошибка запуска.
Не исправлять владельца, направление денег или некорректную версию автоматически.
При ошибке после частичного выполнения можно повторить запуск.

## Совместимость

Web больше не предлагает legacy в выборе, но понимает старые значения в формах,
подписях и API. Android sync push использует те же API-обработчики. Старые offline
операции продолжают приниматься и нормализуются при сохранении. Миграция повышает
версию, поэтому несинхронизированное редактирование на устройстве может потребовать
штатного разрешения конфликта. Локальные кэши обновятся при очередной синхронизации.

Проверка: `node --test scripts/migrateTransactionCategories.test.mjs` (для
интеграционного теста нужен `mongod` или `MONGOD_BINARY`).

Локальная проверка 26.09.2026: MongoDB-тест прошёл (включая сохранение типа
расхода, повторный запуск и конкурентное изменение), production build и точечный
ESLint прошли. Форма проверена Playwright/Edge на временной БД при 1365/390 px,
light/dark: актуальная категория старой записи, очистка связей мышью и клавишей
Enter, сохранение в БД, отсутствие ошибок консоли. Рабочая БД не изменялась.
