Аудит: 2026-09-15.

- `vedelo.ru` и `www.vedelo.ru` указывают на production; TLS работает, `www`
  перенаправляется на apex.
- Google Search Console и Яндекс Вебмастер подтверждены DNS-записями.
- VK ID web включён; публичная конфигурация отдаёт app ID и callback на
  `https://vedelo.ru/api/vk-id/callback` без секрета.
- Canonical, robots и sitemap нового origin используют `vedelo.ru`.
- Код переведён на счётчик Яндекс Метрики `112668604`; сырой HTML-код счётчика
  не дублируется, Webvisor не включён, загрузка начинается после согласия.
- На новом origin убрана пользовательская подпись «ранее ArtistCRM»; она
  сохранена только в безопасном сценарии переноса старой PWA.
- PWA-иконки используют versioned URL `/icons/vedelo-v1/**`; прежние пути
  сохранены для legacy-совместимости, но больше не мешают WebAPK загрузить новый
  логотип из-за `immutable`-кэша.
- Регистрация web/Android разделяет Пользовательское соглашение, ознакомление с
  Политикой и отдельное согласие на обработку персональных данных; сервер
  сохраняет дату и версии документов.
- После production-деплоя 1.20.1 автоматическая SEO-проверка прошла для всех 16
  публичных страниц, robots.txt и sitemap.xml; IndexNow принял 16 URL (`HTTP
  202`). Браузерный desktop/mobile smoke регистрации и отдельного согласия на
  Метрику прошёл без ошибок консоли и горизонтального переполнения.
- Лабораторный Lighthouse mobile главной: performance 96, accessibility 96,
  best practices 100, SEO 100; LCP 1,6 с, CLS 0,001.

## Обязательные действия после деплоя

1. В счётчике 112668604 создать цели из `docs/SEO_POST_DEPLOY.md` и проверить
   цепочку CTA → регистрация → первая работа в чистом профиле.
2. Опубликовать новую редакцию документов и проверить `/privacy`, `/terms`,
   `/personal-data-consent`, `/payment`, `/account-deletion` на desktop/mobile.
   До включения серверного требования выпустить Android `versionCode 18`: старые
   сборки без отдельного флажка соглашения смогут входить в существующий аккаунт,
   но не смогут зарегистрировать новый.
3. Для созданного `vedelo@inbox.ru` проверить приём, отправку и восстановление
   доступа; затем применить `NEXT_PUBLIC_SUPPORT_EMAIL=vedelo@inbox.ru` в
   production env и пересобрать приложение.
4. Сначала развернуть migration-capable сборку 1.20.1 или новее также на
   `artistcrm.ru`: сейчас legacy-origin отдаёт старый service worker
   `artistcrm-custom-sw-v3`, старый счётчик 108801563 и `404` для
   `/api/domain-migration/status`. После повторной проверки обоих origin провести
   30-дневную migration campaign, задав один неизменный
   `BRAND_MIGRATION_STARTED_AT`. Немедленный жёсткий redirect сломает перенос
   сессий и push установленной PWA.
5. После старта переезда применить инструменты смены адреса в свойствах старого
   домена Google Search Console и Яндекс Вебмастера, повторно отправить sitemap и
   контролировать `301/308` без циклов.
6. Проверить OAuth, платежи, webhooks, push и PWA на обоих origin по
   `docs/BRAND_AND_PWA_MIGRATION.md`.

## Почта `vedelo@inbox.ru`

На дату аудита корпоративная почта на своём домене входит в платные тарифы
Яндекс 360 для бизнеса; минимальный публичный тариф — 319 ₽ в месяц за
сотрудника. Вместо платной организации создан бесплатный внешний ящик
`vedelo@inbox.ru`; MX, SPF, DKIM и DMARC домена `vedelo.ru` для него не нужны.

Оставшиеся действия:

1. Проверить приём, отправку, попадание не в спам и восстановление доступа.
2. Установить `NEXT_PUBLIC_SUPPORT_EMAIL`, `TOCHKA_RECEIPT_EMAIL` и
   `VAPID_SUBJECT`.
3. Если приложению нужна системная отправка, создать отдельный пароль Mail.ru для
   внешнего приложения и настроить `smtp.mail.ru:465`, `SMTP_USER`,
   `SMTP_PASSWORD` и `MAIL_FROM`. Обычный пароль ящика не использовать.
