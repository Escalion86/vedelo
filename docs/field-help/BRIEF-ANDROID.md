# Внедрение согласованных подсказок в Android

## Цель и контракт

Добавить подсказки во все реально существующие пользовательские эквиваленты утверждённых полей. Это не создание новых экранов и не перенос администрирования. Все 94 записи должны получить явный результат в отчёте: реализовано, частично применимо, нет эквивалента, только веб. Отсутствие экрана не заменять фиктивным UI.

Прочитать `AGENTS.md`, `docs/AI_HANDOFF.md`, `docs/UI_CONVENTIONS.md`, релевантный roadmap. Источники: `APPROVED.json`, `MATRIX.json`, `helpers/fieldHelp.json`; мобильное зеркало `mobile/src/shared/domain/fieldHelp.generated.json` генерируется `node scripts/generateFieldHelp.mjs`. Ручная правка зеркала запрещена. Импортировать `getFieldHelp`, `FieldHelpKey` из `mobile/src/shared/domain/fieldHelp.ts`, без сетевого чтения и без зависимости от DOM/Next.

Оригинал сохранён побайтно. Смысловые ключи — отдельный явный реестр в матрице, не порядковые номера. JSON-зеркало находится внутри mobile, поэтому не требуется изменять Metro, TypeScript, зависимости или сборку. Проверка типов и тест реального JSON-import через существующий `jest-expo` выполнены в подготовке; это не сборка APK.

## Нативная подсказка

Компонент не существует в текущем коде: планируемый новый файл `mobile/src/shared/ui/FieldHelp.tsx`, а не импорт веб-`FieldHelp`. Значок информации справа от подписи, отдельный `Pressable`, доступное имя «Подсказка: …», состояние раскрытия, зона касания не меньше 44×44. Не делать вложенный `Pressable` в кнопку/выбор статуса.

Короткое нажатие открывает текст, повторное закрывает. Использовать лёгкое нативное модальное окно с прокручиваемым текстом, явной кнопкой закрытия, закрытием по фону и Android Back (`onRequestClose`). Сохранять данные и клавиатурный фокус редактора; значок не переключает выбор, не выполняет сохранение и не запускает серверные действия. Светлая/тёмная темы — через действующую палитру `ThemeProvider`, без локальных цветов. Не скрывать актуальный `Notice`/ошибку.

## Реальные пробелы и частичный паритет

Для каждой записи матрица содержит `android.state`, конкретный якорь и `webTransition`. Не обобщать «всё остальное через веб» — большинства таких кнопок в коде нет.

- Все КП (`proposal.*`): нативного редактора/шаблонов/применения и пункта веб-перехода нет. Нативные «Документы» — DOCX, не КП. Не создавать КП и API ради подсказок.
- Отзывы (`review.*`): `/more/client-reviews` — заглушка из `navigation/menu.ts`, рендерится в `mobile/app/more/[section].tsx`; кнопки открытия веба нет. Не выдавать заглушку за форму отзыва.
- `client.conversationLink`: в `ConversationDetail.tsx` есть просмотр связанных клиента/работы, но нет управления привязкой диалога. Объединение клиентов существует и не заменяет привязку переписки.
- Адрес: комментарий существует; сохранения в пул, координат и навигационных ссылок в редакторе нет.
- Статистика: прибыль и маржа существуют; прогнозной диаграммы и помесячного UI нет. Вместо «Учитывать заявки» — отдельный фильтр статуса «Все»/«Заявки», не флажок добавления к прежней выборке. Не прикреплять утверждённый текст к фильтру «Заявки» с ложным обещанием смешанной выборки. Возможность зафиксировать как частичную, без изменения фильтра/формул.
- Настройки: терминология есть; переключателя двух веб-форм и стандартной длительности нет. Часовой пояс показан в уведомлениях, но не редактируется. Подсказка к отображению не должна обещать выбор региона на этом экране; при отсутствии корректного места зафиксировать частичное покрытие, не добавлять настройку.
- Google: синхронизация и её уведомления есть. Редактирования состава передаваемых данных нет, показано сообщение о Web/PWA без кнопки перехода. Единственный существующий переход рассматриваемого набора — «Открыть Google-импорт в web» в `CalendarImportSection.tsx`, URL `https://vedelo.ru/cabinet/import` из `calendarImportApi.ts`. Сохранить его, вход в браузере остаётся отдельным.
- Webhook: Novofon показывает/копирует одноразовый адрес после подключения; в форме Avito/VK отображения webhook нет. Подтверждение Callback VK есть, отдельного редактирования секрета Callback нет. Не запрашивать/возвращать новые секреты ради справки.
- Telegram Business: только чтение состояния, настройки автосоздания клиентов нет.
- Документы: вложения существуют и в draft, но генерация DOCX разрешена только для подтверждённой синхронизированной работы. Утверждённый общий текст хранить целиком, существующее предупреждение о генерации обязательно оставить видимым; не снимать guard.
- `notifications.device`: исходный текст явно говорит о браузере/веб-версии, а здесь Expo push. Хранить исходник без сокращения; если показывать его в нативном контексте, рядом явно обозначить, что описание относится к веб-устройствам, а в Android регистрируется само приложение. Без этой оговорки пометить запись как платформенно неприменимую, а не выдавать ложный текст.
- Семь `admin.*` — только веб. Не добавлять пользовательские мобильные админ-функции.

Тексты повторно не согласовывать и не менять без фактической платформенной причины. Если смысл не подходит реально существующему контролу, отметить ограничение в отчёте; не менять сам каталог и бизнес-логику.

## Границы

Только справочные компоненты/пробрасывание текста и тесты. Не менять offline/storage/outbox, сериализацию черновиков, даты/timestamps, JSON DTO, API, tenant/auth, тариф, модели, формулы статистики, секреты, настройки интеграций, build-конфиги, package ID `ru.escalion.vedelo`, схемы `vedelo://`/`artistcrm://`. Не менять веб-экраны, защищённые файлы и чужие изменения. Не создавать новые пользовательские разделы. Не коммитить, не пушить, не выпускать APK без отдельной задачи.

## Приёмка и команды

1. Каждая из 94 строк имеет явный итог; все существующие применимые поля покрыты, семь админских исключены обоснованно.
2. Нативные подсказки открываются и закрываются без изменения черновика/запросов. Проверить два одновременно достижимых поля, повторное открытие, Android Back и уход со страницы; текст не переносится на соседний экран.
3. Светлая/тёмная темы, узкий экран, увеличенный шрифт, прокрутка длинного текста и зоны касания. TalkBack читает имя/состояние, закрытие возвращает доступный фокус. Браузерный стенд не доказывает нативный Back/TalkBack.
4. Все 94 текста мобильного каталога равны веб-каталогу; неизвестный ключ отклоняется TypeScript, ничего не подгружается через сеть.
5. Сохранены видимые предупреждения и guard генерации/платного импорта, состояния read-back, условные поля и API-действия.

В корне: `node scripts/generateFieldHelp.mjs --check`, `node --test tests/fieldHelpCatalog.test.mjs`.
В `mobile`: `npm run typecheck`; `npm test -- --runTestsByPath src/shared/domain/fieldHelp.test.ts` и точные компонентные тесты всех изменённых экранов/нового `FieldHelp`. Затем полный `npm test` отдельным длительным процессом с завершением 0, не одновременно с build/typecheck; тайм-аут не считать успехом.

`REPORT-ANDROID.md` должен перечислять ключи, отсутствующие эквиваленты и реальные переходы, фактические команды/коды, проверки нативного устройства и непроверенные пункты. Сборка, установка APK и выкладка — отдельные факты, не следуют из успешного Jest.
