# Реферальная система

Проверено локально 2026-09-16.

## Регистрация

- Web/PWA: `/login?mode=register&ref=<ObjectId пригласившего>` передаёт реферера при регистрации по телефону и через VK ID.
- VK присваивает реферера только при создании пользователя. Вход или повторная регистрация существующего аккаунта не меняют привязку. Добавление пароля к существующему VK-аккаунту также не создаёт новую реферальную связь.
- Неверный ID, отсутствующий пользователь и самоприглашение игнорируются. Юридические согласия по-прежнему обязательны.
- Android: ссылка «Продолжить в установленном приложении Android» на web-странице приглашения открывает `vedelo://login?mode=register&ref=...`. Основной и legacy schemes сохраняются. Приложение хранит приглашение в SecureStore до 30 дней, передаёт его в телефонную/VK-регистрацию и очищает после успешного входа. Само посещение web-ссылки не переносит данные в отдельно открытое приложение и не обеспечивает deferred deep linking после установки.
- Изменения Android требуют новой сборки. В уже установленных старых версиях регистрация по ссылке остаётся доступна в браузере.

## Начисления и повторная обработка

`server/referralRewards.js` начисляет процент только с успешного пополнения баланса. Прямая покупка тарифа и системные бонусы не участвуют; ручное пополнение — только с явным выбором администратора. Процент берётся из глобального `SiteSettings.referralProgram.percent`, по умолчанию 5; сумма округляется вниз до рубля.

1. Подтверждённое пополнение сохраняет `referralRewardPending: true` перед попыткой выдать бонус. Для ручного пополнения флаг сохраняется только при согласии администратора.
2. Создаётся платёж бонуса в статусе `pending`. Его детерминированный `_id` и уникальный индекс по исходному платежу защищают от конкурентных дублей. Сумма и процент фиксируются в этой записи.
3. Одним Mongo update меняются баланс пригласившего и скрытая отметка `Users.referralRewardCredits.<rewardId>`. Фильтр включает владельца, tenant и отсутствие отметки. Это работает и на standalone MongoDB без транзакций.
4. Бонус переводится в `succeeded`, затем снимается `referralRewardPending` с исходного платежа. Повтор после сбоя продолжает операцию, не увеличивая баланс второй раз.

ЮKassa/Точка повторяют незавершённый бонус при повторном webhook/sync, не начисляя повторно исходное пополнение. Существующий защищённый `POST /api/billing/renew` также обрабатывает до 100 ожидающих начислений за запуск, включая явно разрешённые ручные бонусы. Ответ содержит `data.referrals.completed/failed`. Для фонового восстановления этот billing cron должен регулярно запускаться в production с существующим `BILLING_CRON_SECRET`; изменения расписания автоматически не выполняются.

Реферальная статистика учитывает только `succeeded`. Удаление ожидающего бонуса или пополнения с незавершённым бонусом возвращает 409 до завершения обработки. Удаление выданного бонуса сохраняет скрытую отметку на пользователе, чтобы replay не восстановил удалённое начисление; это распространяется и на удаление старых бонусов после обновления.

## Совместимость и пределы восстановления

Старые успешные бонусы считаются выданными. Если старая версия сохранила `succeeded`, но не изменила баланс, по одной этой записи нельзя безопасно определить, получил ли пользователь деньги. Исторические суммы автоматически не пересчитываются: требуется отдельная сверка. Новая очередь не включает старые пополнения без `referralRewardPending`.

Отметки `referralRewardCredits` нельзя удалять при обычной чистке истории: они обеспечивают защиту от повторного зачисления. Поле исключено из стандартных запросов Mongoose через `select: false`.

## Проверка

```sh
node --test server/referralRewards.test.mjs server/referralSummary.test.mjs tests/server/referralFlow.integration.test.cjs
node --test tests/mobile/http.integration.test.js
cd mobile
npm run typecheck
npm test
```

Интеграционный тест запускает отдельный локальный `mongod`, использует настоящие схемы/индексы и синтетические данные, проверяет VK-регистрацию, tenant-negative сценарий, конкурентные начисления, ошибки записи и потерю подтверждения, retry обоих провайдеров и удаление бонуса. Production-БД и настоящие VK/платежи тесты не используют.
