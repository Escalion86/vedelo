# Обновления Android «Ведело»

С Android 1.1.5 откройте **Меню → Настройки → Обновление приложения**. Сборка с APK показывает установленную версию и сравнивает код сборки с опубликованным. Если доступна более новая версия, кнопка «Скачать APK» открывает официальный HTTPS-адрес. После скачивания откройте файл и подтвердите обновление в Android. Сборка Google Play открывает карточку приложения в магазине. [Правила обновлений Android](https://developer.android.com/google/play/app-updates).

Первый переход со старой версии на 1.1.5 выполняется установкой подходящего APK поверх текущего. Android сохраняет данные при совпадающем пакете и сертификате и подходящем `versionCode`. У обычного локального APK и облачного APK EAS одинаковый пакет и разные подписи. Для обновления установки EAS используйте новый APK, подписанный её существующим ключом EAS. [История локального ключа](AI_HANDOFF.md#L1749), [подпись приложений](https://developer.android.com/studio/publish/app-signing).

## Публикация

| Сборка | Пакет | Источник обновления |
| --- | --- | --- |
| Обычный локальный APK | `ru.escalion.vedelo` | Переменная `ANDROID_APK_RELEASE`, локальный сертификат релизной линии |
| EAS `production-apk` | `ru.escalion.vedelo` | `ANDROID_EAS_APK_RELEASE`, прежний сертификат EAS |
| «Ведело Dev» | `ru.escalion.vedelo.dev` | `ANDROID_DEV_APK_RELEASE`, прежний сертификат Dev |
| EAS `production` для Google Play | `ru.escalion.vedelo` | Обновление через магазин |

1. Соберите APK предусмотренного канала и подпишите его прежним ключом этого канала. Сверьте `packageName`, `versionName`, `versionCode` командой `aapt dump badging` и сертификат командой `apksigner verify --print-certs`. Для нового релиза код сборки должен быть выше предыдущего.
2. Разместите APK по доступному без входа HTTPS-адресу на `vedelo.ru` или `cloud.escalion.ru`. Используйте отдельный URL для каждой версии, чтобы скачивался файл, соответствующий метаданным.
3. Задайте переменную нужного канала на сервере и примените конфигурацию. Значение берите из результатов проверки APK. Пример JSON для локальной релизной линии приведён ниже.

```json
{"packageName":"ru.escalion.vedelo","versionName":"1.1.5","versionCode":31,"downloadUrl":"https://vedelo.ru/downloads/vedelo-1.1.5-31.apk"}
```

Публичный `GET /api/mobile/v1/app-update?packageName=ru.escalion.vedelo` возвращает только эти четыре поля. Для облачной APK-линии добавляется `channel=eas-apk`. Ответ `data: null` означает, что канал пока не опубликован. Клиент предлагает APK при `versionCode`, превышающем код установленной сборки. Закрытые ключи и пароли нужны только при подписи. [Маршрут метаданных](../app/api/mobile/v1/app-update/route.js), [профили EAS](../mobile/eas.json).

Проверяйте обновление на установке того же канала и устройства. Пройдите состояние без публикации, проверку той же версии и обновление поверх предыдущего APK. После установки проверьте версию, сохранение входа и локальных данных. Настройка серверного канала и публикация APK выполняются отдельно для каждого выпуска.

В 1.1.5 прошли TypeScript и 52 теста в трёх наборах настроек Android. Локальный HTTP-стенд подтвердил метаданные без авторизации и кэширования, ответ для непубликованного канала и отказ для старого package ID. Серверные тесты дополнительно проверили разделение линий подписи и отклонение посторонних адресов. Телефон и AVD через ADB не обнаружены.

Локальный `vedelo-1.1.5-31-local.apk` собран для ARM64 и ARMv7 с Android 10+. Сертификат совпадает с `vedelo-1.1.3-29-local.apk`. SHA-256 файла `4d238aa25f90b4cd572be52e38ad9ef917aafa78c02e428bbdc87738aa20d839`. На 25 ноября 2026 года рабочий `vedelo.ru` отвечал HTTP 404 на проверку обновлений. Для запуска канала требуется выложить маршрут и опубликовать метаданные подписанного APK.

`vedelo-dev-1.1.5-31-arm64.apk` собран для ARM64 с Android 10+. Сертификат совпадает с `vedelo-crm-updates-20261110-arm64.apk`. SHA-256 файла `f42e905a411440f08d0a4d90644ec0c9803bca9576e1b3242ae735ff4fd6ba02`. Наличие экрана обновления и вызова API подтверждено в Hermes bundle обоих APK.
