# DOCX: документы в Ведело

## Что умеет система

- Формирует документы в `.docx` из пользовательских шаблонов.
- Подставляет переменные из карточки мероприятия, клиента и настроек реквизитов артиста.
- Поддерживает:
  - несколько пользовательских DOCX-шаблонов;
  - названия шаблонов;
  - типы документов: `Договор`, `Счет`, `Чек`, `Акт`, `Другое`;
  - стандартные DOCX-шаблоны договора и акта как примеры/fallback.

## Web/PWA: независимые документы

КП, договор, счёт, чек и акт не требуют друг друга. Документы доступны и у заявки (`draft`), независимо от флага «По договору».

1. В редакторе заявки/заказа откройте «Файлы и документы → Добавить документ».
2. Сначала выберите тип: договор, счёт, чек, акт или другой документ.
3. Загрузите готовый файл, добавьте ссылку либо нажмите «Сформировать».
4. Для формирования выберите DOCX-шаблон нужного типа и дату. Используются **сохранённые** данные заказа: изменения формы сначала нужно сохранить. Если к заказу применено КП, его согласованный состав и стоимость можно выбрать отдельно.
5. «Проверить данные» показывает значения переменных, неизвестные теги и незаполненные поля. Это проверка содержимого, а не постраничный просмотр Word. Неизвестные переменные нужно исправить в шаблоне; пустые известные поля допускаются только после явного выбора.
6. «Создать документ» назначает номер, формирует файл и автоматически прикрепляет его. Нажатие на файл открывает сохранённый экземпляр; новый документ создаётся отдельно.

Номер выдаётся сервером отдельно для каждого типа. Повтор запроса после сетевого сбоя сохраняет тот же номер и файл; параллельное резервирование может оставлять пропуски в последовательности. Для повтора сервер временно хранит снимок шаблона и переменных в tenant-scoped `DocumentGenerations`; после сохранения файла бинарное содержимое шаблона из записи удаляется. Метаданные и значения остаются для истории.

Чек добавляется **готовым файлом или ссылкой** из сервиса, в котором он выдан. Формирование DOCX под названием «чек» в новом web-сценарии недоступно. Связь с конкретной оплатой необязательна; её можно изменить позже кнопкой «Связать с оплатой» / «Изменить оплату». Подсказка об отсутствующих чеках учитывает денежные поступления заказа, исключая расходы, бартер и обязательства. Несколько частичных оплат могут иметь отдельные чеки. Подсказка не блокирует работу.

Дополнительные переменные web-генерации: `{ДАТА_ДОКУМЕНТА}`, `{СУММА_ДОКУМЕНТА}`. Для независимого счёта/акта дата договора автоматически не выдумывается: используйте дату документа, если договор не нужен.

Web endpoints: `POST /api/events/[id]/documents/generate` (проверка `action: preview` или создание с `requestId`), `POST /api/events/[id]/documents` (ссылка), `PATCH /api/events/[id]/documents` (связь чека с оплатой). Все операции проверяют сессию, tenant, тариф и принадлежность оплаты заказу.

Android в эту доработку не входит; его существующий endpoint и клиентский сценарий не менялись.

## Ограничение по тарифу

- Функционал доступен только если тариф разрешает `Работа с документами` (`allowDocuments = true`).
- Если доступа нет:
  - на странице `Документы` показывается уведомление о недоступности;
  - в редакторе мероприятия скрыт блок `Сформировать документ`;
  - скрыт блок `Документы мероприятия`.
- Чекбокс `По договору` в мероприятии виден всегда.

## Где хранятся шаблоны

Пользовательские шаблоны сохраняются в `SiteSettings.custom.documentTemplates[]`:

- `id`
- `name`
- `type`
- `customTypeName`
- `fileName`
- `templateBase64`
- `createdAt`
- `updatedAt`

Legacy-поля поддерживаются только на переходный период:

- `contractDocxTemplateBase64`
- `contractDocxTemplateFileName`
- `actDocxTemplateBase64`
- `actDocxTemplateFileName`

Стандартные шаблоны (fallback) берутся из:

- `public/templates/default-contract-template.docx`
- `/api/document-templates/examples/act` — DOCX-пример акта создаётся при скачивании, без отдельного бинарного ассета.

## Специальные переменные (важно)

### `{РЕКВИЗИТЫ_СТОРОН}`

В DOCX заменяется на табличный блок:

- слева таблица `Исполнитель` (реквизиты артиста),
- справа таблица `Заказчик` (реквизиты клиента).

Пустые значения оставляются пустыми (без `_______`).

### `{ПОДПИСИ_СТОРОН}`

В DOCX заменяется на таблицу `2x2` без рамок:

- `1,1` — `Исполнитель`
- `1,2` — `Заказчик`
- `2,1` — `Фамилия И.О. исполнителя + "_______________"`
- `2,2` — `Фамилия И.О. заказчика + "_______________"`

## Имена итоговых файлов

- Договор: `Договор №<номер> от <dd.mm.yyyy>.docx`
- Акт: `Акт №<номер> от <dd.mm.yyyy>.docx`

## Где задаются реквизиты артиста

- `Документы -> Редактировать реквизиты`
- Юр. статус артиста:
  - `Индивидуальный предприниматель`
  - `Самозанятый`

Для режима `Самозанятый` поле `ОГРНИП` не обязательно.
