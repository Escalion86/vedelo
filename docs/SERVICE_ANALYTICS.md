# Аналитика сервиса

Первый этап, 23.09.2026. Web/PWA: `/cabinet/service-analytics`, пункт меню разработчика «Аналитика сервиса». API: `GET /api/developer/analytics`.

## Вкладки

- **Обзор**: регистрации, поступления, плательщики, первые оплаты, конверсия за 30 дней, два дневных графика, неуспешные операции и сроки тарифов.
- **Деньги**: первые/повторные платежи, средний платёж, категории внутреннего баланса и назначенные тарифы на текущий момент.
- **Рост**: регистрации по дням, этапы освоения CRM, источники и кампании.

Период (7/30/90 дней или 1–366 дней вручную), вкладка и исключения аккаунтов хранятся в URL. Все границы дней — UTC. Сегодняшний день считается только до времени запроса; предыдущий период имеет такую же фактическую длительность. В интерфейсе указаны период сравнения и время загрузки. Данные в React Query актуальны 60 секунд, обновление доступно вручную.

Карточки открывают список соответствующих пользователей (по 25 записей на странице); имя открывает существующую историю расчётов. Средний платёж и число платежей детализируются списком плательщиков. У конверсии показывается созревшая регистрационная группа. В таблицах графиков доступны точные дневные значения без наведения указателя. Таблицы на мобильном прокручиваются внутри блока.

## Правила денег

- Поступления: `Payments.type=topup`, `source=tochka|yookassa`, `status=succeeded`, положительная сумма.
- Плательщик — уникальный `userId` среди таких поступлений в периоде.
- Первая оплата определяется по всей доступной истории внешних успешных платежей, а не только по выбранному периоду. Повторные платежи = число платежей − число впервые оплативших.
- Средний платёж = поступления / число успешных внешних платежей.
- Списания за тариф, ИИ, прочие списания, ручные пополнения, бонусы и возвраты на баланс показаны отдельно. Их нельзя прибавлять к поступлениям.
- Незавершённые реферальные начисления `referralRewardPending=true` исключены.
- Дата операции — `paidAt`, при отсутствии — `createdAt`. Для ручной операции это может быть введённая прошлая дата; `recordedAt` не используется для группировки.
- Назначенный тариф не доказывает оплату: он мог быть выдан вручную. Пробный доступ определяется по `trialEndsAt`; истёкший указанный срок тарифа отмечен в названии группы.
- Банковские возвраты, эквайринговые комиссии, прибыль, MRR и прогноз продлений на первом этапе не рассчитываются.

## Рост и полнота данных

Группа — пользователи, зарегистрированные в выбранный период по `Users.createdAt`. Источник: `acquisition.source`, fallback `registrationSource`, иначе «Без источника». Кампания: `acquisition.campaign`.

Конверсия за 30 дней: успешная первая внешняя оплата в интервале `[регистрация, регистрация + 30 дней)`, делённая на число регистраций, у которых к моменту запроса завершились все 30 дней наблюдения. Несозревшие регистрации исключены из знаменателя; при пустом знаменателе результат отсутствует, а не равен нулю. Поэтому на периоде последних 7/30 дней конверсия часто ещё недоступна; для анализа выбирайте более раннюю группу.

Этапы из `acquisitionFunnel` показывают достижения выбранной регистрационной группы **по состоянию на сегодня**. Это независимые этапы: оплата не требует завершения знакомства или создания заказа. Старые аккаунты без отметок нельзя интерпретировать как достоверно не использовавшие функцию. Конверсия рассчитывается по Payments, а не по исторической метке `paymentSucceededAt`.

Разработчики и администраторы исключаются автоматически. До 100 других аккаунтов можно исключить явно; список относится только к текущему URL отчёта и не меняет учётные записи. Удалённые пользователи и удалённые операции не восстанавливаются: отчёт отражает доступную текущую базу. Для бухгалтерской сверки нужен отдельный неизменяемый реестр.

## Доступ и реализация

Это намеренно глобальный отчёт по сервису, аналог developer-only `/api/billing/operations`; обычный tenant-фильтр к агрегатам не применяется. До чтения проверяются авторизация, валидный tenant-контекст и `role=dev`; роль повторно читается из Users. Admin и обычные пользователи получают 403, анонимный запрос — 401. Переданный клиентом tenant не меняет область доступа. Ответ имеет `Cache-Control: private, no-store`.

В браузер передаются суммы, счётчики и ограниченный список пользователей (ID, имя, даты и рассчитанные показатели). Пароли, телефоны, адреса, provider payload, токены и служебные ключи не выбираются и не сериализуются. Mongo группирует платежи до отправки; запросы агрегатов ограничены 15 секундами. Пользовательская база пока загружается целиком в ограниченной проекции: при существенном росте аудитории потребуется отдельная серверная пагинация детализации и материализация агрегатов.

Файлы: `server/serviceAnalytics.mjs`, `app/api/developer/analytics/route.js`, `layouts/content/ServiceAnalyticsContent.js`.

## Основа для «Использования»

`ServiceActivityDays` сохраняет один факт посещения на пару tenant/user за UTC-день: `tenantId`, `userId`, `day`, `firstSeenAt`. Уникальный индекс защищает от дублей; tenant берётся из загруженного пользователя, а не из payload. Запись подключена к существующему `recordCabinetVisit` при открытии/смене страницы Web/PWA. Ошибка аналитического хранилища не блокирует кабинет.

Это факты посещения, а не полный журнал действий или времени работы. Android, активность непрерывно открытой страницы без навигации, события использования функций и историческое восстановление сюда пока не входят. Вкладка удержания будет отдельным этапом после накопления данных; нули за время до внедрения не рисуются.

## Проверки

`node --test server/serviceAnalytics.test.mjs tests/server/serviceAnalytics.integration.test.cjs`

Интеграционные тесты запускают установленный `mongod` на свободном порту с временной БД, проверяют настоящий handler, агрегации, отказ чужим ролям и дневную дедупликацию. Production-данные не используются. UI проверен в изолированном Playwright-стенде на 1365×900 и 390×900 (dark): вкладки, выбор периода, исключения, детализация, ошибка API и отсутствие горизонтального переполнения страницы. Полный вход разработчика в production и реальная история платежей в браузере не проверялись.
